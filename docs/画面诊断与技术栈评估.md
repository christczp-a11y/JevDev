# 3D 版的问题诊断、纸片马力欧和上美影的研究、技术栈评估（2026-09-29）

> 起因：Chris 看完云端做的徙木立信 3D 修正版（161 秒）：「不能用……视觉改完后还不如纯 2D 横向卷轴」「景深不够导致场景小气，逻辑部分大多不合理，运镜混乱」。他要求好好研究纸片马力欧的场景和上美影的运镜，再评估 three.js 适不适合，不行就换技术栈。
> 做法：
> - 4 份并行调研（Sonnet 5.5）：逐条诊断，本地显卡截 3D 和 2D 同一时刻的画面对比；纸片马力欧；上美影；技术方案比较，并在本机实测了 Blender。
> - Opus 5.5 汇总判断。
>
> 逐条的问题记录在 `memory/PITFALLS.md` 的 T11–T18 和 P9。

## 一、结论
1. **不换技术栈，但彻底改变用法。** three.js 保留，从「自由转动的 3D 镜头」改成「**2.5D 多层摄影台**」：镜头基本正对舞台，只做平移和推拉；场景分 5–7 层，有视差；按层做景深。这就是上美影剪纸片和纸片马力欧过场的做法，three.js 完全能做到。
2. **这次的问题，绝大多数不是 three.js 的问题。** 8 条里有 6 条是 bug 或者缺规则（朝向标错、画布切掉鞋底、2D 道具照搬、镜头只按人数构图、开场镜头太短）。换 Blender 的话，纸片一样是平面，这些问题照样会出。
3. **做法本身的限制有两条**，要写成规则来绕开：
   - 素材原图只有 500 像素左右高，特写一放大就糊。所以特写要专门画高清素材，放大倍数 ≤ 1.3；
   - 纸片角色只有朝左、朝右两个状态，镜头斜过 60° 就变成一张薄片。所以镜头左右偏转限制在 ±15°，最多 ±30°。
4. **Blender 暂时不换。** 画质上限最高（真景深、纸张材质），本机也跑通了，但比 three.js 慢 2.5–14 倍，云端没有显卡也出不了片。留作以后「精修版」的候选。
5. 下一步：**先用一场做对比试验**，再决定要不要改整集（见第五节）。

## 三、研究要点
### 纸片马力欧（折纸国王、千年之门重制版等）
任天堂几乎没有公开过镜头参数。下面的内容来自开发者访谈、拆包资料和截图观察：
- **显得大**：前景是又大又暗的树和石头，压在画面边上；中景放角色；远景至少 3 层山，越远越浅越蓝，尽头有一个地标；小路斜着伸向远处。**宽镜头不虚化**：模糊加俯视会让东西看起来像微缩模型，反而显得小。
- **镜头**：探索时从后上方跟随，俯角约 25–40°；对话时降到约 15° 的中景。过场用**固定机位，不绕着纸片角色转**，很多角色的背面贴图从来没露出来过。
- **人物在画面里的高度**：宽镜头约 13–18%（建议 10–15%），对话约 25–30%，特写 50% 以上。特写用专门的高清贴图：结局用的 Mario 贴图是 3475×5999 像素。
- **站位**：千年之门战斗时固定「我方在左、对方在右」。对话双方互相转成 3/4 侧面，面向对方。脚踩在地上，有接触阴影。

### 上美影（剪纸片、经典片、中国奇谭）
- **剪纸片的镜头从来不绕着纸片转**：摄影机始终正对画面，只做平移、推、拉。纵深靠多层玻璃分层拍摄（前、中、后景）；《小满》复刻了分层摄影台，做出「2.5 维」的效果。
- **景别**：《三个和尚》前 66 个镜头里，远景加全景约占 78%，特写约 8%；动的镜头只占约 9%，而且多用来「揭示」，比如拉出庙的全貌。
- **节奏**：平均每个镜头约 4.7 秒；高潮约 2 秒一个（这是推算，要复核）。
- **让小孩看得懂**：
  - 人物固定从一边入画；
  - 先看后切：人物先抬眼看，下一个镜头切到他看的东西；
  - 每个角色一个主色，不换装；
  - 对立的双方不放在同一个画面里。
- **侧面纸偶不转身**：需要别的角度，就切一个镜头，换另一套纸偶。《小满》的主角有 10 多套不同比例的纸偶。
- 《中国奇谭》各集用的技术不一样：《小满》是手工剪纸定格，《林林》是全 3D，《小卖部》是三渲二。**没有一部是「镜头绕着纸片转」的**。

## 四、新的镜头和场景规则：「2.5D 摄影台」（替换原来第 6 步的镜头规则）
数值是起步值，对比试验以后再调。

**镜头**
1. 镜头基本正对舞台：左右偏转 ≤ ±15°，最多 ±20°（49 秒那个好镜头就在这个范围里），不绕到侧面和背面。
2. 用长焦：视野角约 15–25°，具体数值由试验定。同一场里视野角不变。
3. 俯角：交代镜头 25–35°，对话 ≤ 15°。
4. 镜头时长：每个镜头 ≥ 2 秒，交代镜头 ≥ 3 秒，一般 3–5 秒，高潮可以 2 秒。开场第一镜从 0 秒起就要有司马光。
5. 动的镜头不超过约 1/5，只用来揭示、跟随动作和高潮；其余镜头固定。
6. **景别按剧情定，不按人数定**。每场的顺序：远景交代时间地点 → 全景人物入画 → 中景对话 → 特写道具或表情 → 回到全景。相邻两个镜头的景别，最多跳两档。
7. 人物在画面里的高度：宽镜头 10–15%，中景 25–30%，特写 ≥ 50%。
8. 每场定一条轴线（我方在左、对方在右），机位留在同一侧。先看后切。
9. 旁白说到谁，谁就是画面主体：最大、最靠前、颜色和背景分得开。

**场景**
10. 每场分 5–7 层：天空、远山（≥ 3 层，越远越浅越蓝）、中景、主体、前景框（暗，压住下缘）。竖屏上下叠层：远山放在上面 1/3。
11. 景深按层模糊，只用在中景和特写；宽镜头不虚化。
12. 故事镜头里拍不到桌面和房间（现有的 `qa` 检查）。
13. 2D 的道具和特效搬进 3D 以前，要重新检查逻辑：书卡、会飞的乌鸦、悬在空中的「罚 / 奖」牌子。

**角色**
14. 每张素材登记原图朝向。角色要面向镜头主体或者说话的人；对话双方互相面对。
15. 纸片在特写里不转身。需要别的角度，就切镜头、换另一张姿势图。
16. 屏幕高度 ÷ 原图高度 ≤ 1.3。特写要专门画高清素材。
17. 脚底贴地：站着时最低的不透明像素就在地面上，并加接触阴影。
18. 主角的素材不许当路人用。

**要新做的自动检查**（加进工作流第 0 步）：镜长、朝向、放大倍数、脚底贴地、字幕和画面主体的对应、相邻镜头的跳动和景别顺序、新旧版逐场并排对比。

## 五、技术方案比较（本机 GTX 1660 Ti 实测 + 资料）
| | A three.js（改成 2.5D 用法） | B Blender | C 纯 2D 多层视差（现有 Canvas 引擎） | D Godot |
|---|---|---|---|---|
| 画面上限 | 中高。透明纸片的景深要自己按层做，现成的 BokehPass 会把整张矩形卡片当成一个深度 | 最高：真景深、纸张材质、柔和阴影 | 中：没有真实投影，纸片不能翻页、弹起 | 高 |
| 复用现有纸偶和素材 | 全部 | 静态图可以直接用；纸偶要先导出成 PNG 序列 | 全部 | 要重新导入 |
| 本地每秒成片耗时 | 3.2–7.7 秒（实测） | EEVEE 19–45 秒，Cycles 200–350 秒（实测，场景还很简单） | 未测，应该最快 | 未测 |
| 云端（没有显卡） | 89 秒 | 基本出不了片 | 可以 | 要软件 Vulkan |
| 自动质检 | 已经有一部分 | 要重写 | 最容易 | 要重写 |
| 迁移工作量（估计） | 1–3 天 | 1–2 周 | 3–5 天 | 2–3 周 |

排序：**A（按第四节的规则用 three.js）** > C（保底：A 的景深做不好，或者需要在云端出片时用）> B（以后精修的候选）> D（没必要）。

**先说结论（TL;DR）**
1. 流传最广的「CES 评分公式」和「流量池精确档位」**都没有官方出处**，不同文章给出的权重甚至互相矛盾。能确定的只是方向：先小范围试投，数据好再扩大；而且越「费力」的互动（评论、分享、关注）大概率越重要。
2. 官方能确认的有：推荐系统利用点击、搜索、点赞、收藏、评论等行为和笔记内容本身做匹配 [S6][S7][S8]；**70% 的月活用户会主动搜索** [S9]。所以对美食账号来说，**搜索流量和推荐流量同样重要**，标题和正文里的关键词要认真布局。
3. 双列信息流里，用户只看得到**封面 + 标题**，所以点击率是第一道门槛（共识）。3:4 竖版封面、首图一眼能看出「哪里 + 吃什么 + 为什么值得去」。
4. 硬红线【官方】：诱导互动（求赞、求收藏、求关注、「评论扣 1」）、导流（微信号、其他平台）、极限词、未标注的 AI 内容、搬运他人图片、未报备的商业合作、伪装素人。**我们的自动化工作流用 AI 写稿，所以必须每篇都标注 AI。**
5. 学术研究的结论：高唤起情绪、实用价值、好奇心缺口、具体化能提高点击和转发；但**爆款在很大程度上不可预测**（MusicLab；Twitter 级联研究中，最好的模型也解释不了一半的方差）。Jev 的分数只能作为**概率排序**使用，必须保留随机探索的名额。

## 1. 小红书推荐机制

### 1.1 官方能确认的部分

- 【官方】**算法备案（2023-12 公示）**：个性化推荐基于设备信息、地理位置、浏览记录，以及点击、搜索、点赞、收藏、评论、发布等互动行为，给用户打兴趣标签后推荐内容；另外还有去重、打散、兴趣探索等干预机制 [S6]。
  → 落地：**地理位置本身就是推荐信号**。温哥华本地用户更容易刷到本地内容，所以地域词和地域标签要写清楚，帮助系统判断这篇笔记属于哪个地方。
- 【官方】**官方论文**：SSD（KDD 2021）已经部署在「发现页」主信息流里，用来做结果**多样性**，同质内容会被打散 [S7]。NoteLLM（WWW 2024）会把笔记内容压缩成向量做「相关笔记」推荐，还会从笔记自动生成话题标签和类目 [S8]。据媒体解读，SSD 的内容向量同时使用了**标题文本和封面图** [S6]（二手解读，论文摘要里没有直接写明）。
  → 落地：标题、正文、话题、封面在**语义上要一致**，系统才能把笔记放进对的兴趣簇；和已有爆款高度雷同的内容会被多样性机制打散，要追求差异化角度。
- 【官方】**搜索**：小红书在 2025 年 4 月公布，70% 的月活用户有主动搜索的习惯，每月有 1.7 亿用户在找购买建议 [S9]。
- 【官方表态，经媒体转述】**去中心化**：平台多次表示，每天有一半以上的泛内容流量分给千粉以下的创作者 [S10]。新号并不天然吃亏，但商业流量另当别论。

### 1.2 CES 评分：【传言】（方向是【共识】）

- 流传版本：CES = 点赞×1 + 收藏×1 + 评论×4 + 转发×4 + 关注×8 [S1][S4]。
- 为什么判为传言：
  - 最早的讨论本身就说这是「市面上流传比较广的说法」，理由是和 B 站公开过的 2020 年公式类似，并没有小红书官方出处 [S2]。
  - 另一篇 2026 年的文章给出了完全不同的权重（关注 10、分享 8、评论 6、收藏 4、点赞 2），同样没有来源 [S3]。
  - 还有「完播率每提升 10% 加成 15%」「CES≥0.7」「长评论超过 15 字权重更高」等说法，都没有出处 [S3]（另见 byerisk 等营销站点，同样无出处）。
- 【共识】可以放心使用的部分：**越「费力」、越代表长期关系的互动（关注、评论、分享），权重大概率越高**；只有点赞、没有收藏和评论，说明内容「好看但没用」。
- 落地：**不要在代码里硬编码 CES 权重**。用我们自己账号的数据回归「互动构成 → 后续曝光」，让数据来决定权重（和 PLAN 阶段 3 一致）。

### 1.3 流量池分级与首轮曝光

- 【共识】机制是「**先小流量测试 → 数据达标 → 推给更大的人群**」，逐级放大，发帖账号粉丝数不是决定因素 [S1][S4][S5]。
- 【传言】具体档位：冷启动 0–200 次浏览（发布后约 2 小时）→ 200–500 → 500–5000 → 1 万以上（据说有人工审核）[S4]；也有说法是 24–48 小时内完成评估 [S1]。有作者用投放后台数据论证过「流量池确实存在」，但同时承认各档没有确定数值，而且不同品类标准不同 [S5]。
- 落地：发布后 **2h / 24h / 72h / 7d** 分别回收数据（PLAN 里已有 24h/72h/7d，建议**加一个 2h**，用来观察首轮点击率）。

### 1.4 点击率（封面 + 标题）

- 【共识】发现页是双列信息流，用户只能看到封面、标题、作者和点赞数；首轮曝光的**点击率**决定能不能进入下一轮 [S4][S5][S11]。
- 【共识】平台为视频笔记提供过封面测试功能：可以上传 4 张封面，约 10 小时后自动选出表现最好的那张 [S11]（这是第三方描述的功能，说明平台自己也把封面当作关键变量）。
- 落地：点击率 = 创作中心「小眼睛」/ 曝光数。标题和封面要**分开评估**（它们是两个不同的刺激），见第 8 节。

### 1.5 搜索流量 vs 推荐流量

- 【官方】70% 的月活用户会搜索 [S9]。
- 【共识】推荐流量来得快、去得快（集中在前几天）；搜索流量是**长尾**，一篇回答了明确问题的笔记（比如「列治文早茶推荐」）可以持续几个月带来流量 [S9][S28]。
- 【共识】搜索路径通常从一级词逐步细化：「城市+美食」→「城市+美食+必吃榜」→「城市+美食+必吃榜+商圈」[S30]。
- 【传言】「搜索转化率是推荐的 3.2 倍」「60% 的用户打开就搜索」「月搜索量 150 亿」等数字没有出处 [S3]。
- 落地：每篇笔记都要有一个**明确的目标搜索词**（例如「本拿比 火锅」「温哥华 生日餐厅」），并放进标题、首句和话题里（见 4.6）。

### 1.6 收藏率与「干货」

- 【共识】清单、榜单、攻略类内容的**收藏/点赞比**明显更高；收藏意味着「以后要用」，也会让用户回访、在搜索中复现 [S1][S23]。
- 【学术，间接】Berger & Milkman 发现，**实用价值**高的内容更容易被分享 [A1]。
- 【传言】「收藏率 ≥5%、评论率 ≥2% 才算达标」等阈值没有出处 [S3]。
- 落地：美食账号里最容易拿到收藏的是「榜单 / 合集 / 按场景分类的清单 / 地图式攻略」。单店笔记要提高收藏率，就得附带可复用的信息（推荐菜清单、点单攻略、避坑事项）。

## 2. 标题

### 2.1 硬限制
- 【官方·产品限制】标题**最多 20 字**（多个来源一致 [S12][S26]）。字数由代码统计（中文、英文、数字、emoji 的计数规则要以 App 实际表现为准，上线前手动测一次）。

### 2.2 高点击标题公式【共识】
多个来源总结的要素 [S12][S13][S23]：**人群 + 场景 + 痛点 + 解决方案 + 结果/情绪 + 冲突感**，底色是**口语化**。拆开来就是：

| 公式 | 机制 | 温哥华美食示例（自拟） |
|---|---|---|
| 数字型 | 具体、可预期、像清单（利于收藏） | 「列治文 7 家早茶，我只回购这 2 家」 |
| 价格/人均型 | 性价比是美食赛道第一需求 | 「人均 $18 吃到撑的本拿比川菜」 |
| 地域词型 | 搜索 + 地理推荐 | 「Kitsilano 周末 brunch 不踩雷清单」 |
| 身份/场景标签 | 让目标人群觉得「在说我」 | 「带爸妈来温哥华，这家粤菜稳了」 |
| 痛点/怕踩雷 | 损失厌恶、焦虑（高唤起） | 「在温哥华吃日料，这 3 种店别进」 |
| 悬念/信息缺口 | 好奇心缺口 [A2] | 「排队 1 小时的网红店，值不值？」 |
| 对比/反差 | 冲突感 | 「$15 的拉面 vs $28 的拉面，差在哪」 |
| 反常识 | 打破预期 | 「温哥华最好吃的越南粉在一家加油站旁」 |

- 【传言】「85% 的爆款标题用了数字」[S12] 只有单一来源。数字有用是【共识】，比例存疑。
- 【共识】可以用少量 emoji 或符号突出卖点 [S12]，但会占用 20 字额度，而且过度堆砌显得像营销号。

### 2.3 美食探店类标题特征【共识】
- 常见结构：**情绪/观点 + 地点/店名/打卡点 + 心得或吐槽** [S23][S30]。
- 高频信息：地域（城市/区/商圈）、品类（火锅、早茶、日料…）、人均价格、场景（约会、一人食、宵夜、带娃）、时效（新开、限定、季节）。
- 落地规则：**20 字里至少包含「地域词」和「品类/店名」中的一个，最好都有**；地域词是搜索和地理推荐的双重信号。

### 2.4 极限词 / 违禁词风险【官方】
- 社区规范禁止夸张、胁迫式表达；社区公约 2.0 反对「夸张博眼球」[S13][S14]。
- 广告法类极限词（平台会限流或删除）：最、第一、唯一、顶级、独一无二、全网最低、国家级、世界级、绝版、万能、神器等 [S19]。美食圈常见的「天花板」「封神」「全温哥华最好吃」「吊打」都属于同类风险（这里是推断：它们在语义上等同于「最」）。
- 其他平台名（淘宝、抖音、B 站等）和它们的谐音、代称不能出现在笔记和评论里 [S19]。
- 落地：代码先用词表做正则拦截；Jev 再用 Noul 兜底识别语义变体（见第 8 节）。
- 注意：「最好吃」这类说法在「个人主观体验」语境下的尺度，各来源说法不一。**保守做法是一律改写**：「我吃过最好吃的…」和「我心里的 No.1」都有风险，改成「我已经回购 4 次」这类可以核实、又不含「最」字的个人事实。

## 3. 封面与配图

### 3.1 规格
- 【共识】**3:4 竖版**（推荐 1080×1440），在双列信息流里占的面积最大 [S11][S27]。同一组图片保持相同比例，否则滑动时会忽大忽小 [S27]。
- 【官方·产品限制】图文笔记最多 **18 张图**（第三方转述 [S26]）。
- 【共识】建议 **4–9 张**，既有信息量，又能拉长停留时间 [S26]。

### 3.2 封面的作用与类型【共识】
- 首图是「第一刺激」，标题是第二刺激 [S12][S11]。
- 适合美食的封面类型 [S11]：①单张高颜值特写；②**统一色调的拼图**（多店合集最常用）；③海报式（主图 + 大字标题 + 副标题）；④前后对比；⑤纯文字 / 信息卡（主打数字、时间、方法）。
- 【共识】封面要有**唯一的视觉焦点**；风格统一的账号封面更容易被系统识别 [S11]。
- 【传言/单一来源】封面文字不超过画面的 1/3、主标题不超过 15 字 [S27]。
- 落地：封面大字**不要和标题重复**，两者应该互补（例如封面写「人均 $18｜本拿比」，标题写「吃到撑的川菜，老板是成都人」）。

### 3.3 真实感 vs 精修
- 【共识】过度修图失真、广告感太重是探店笔记的常见坑 [S30]；平台价值观强调「真诚分享」，反对「过度包装」[S14]。
- 【学术】Li & Xie（2020）在 Twitter/Instagram 上发现，**高质量、专业拍摄的图片**会稳定提升互动 [A7]。
- 两者并不矛盾：要**清晰、光线好、构图干净**（质量），但**不能失真**（滤镜改变食物颜色、P 掉环境、摆拍出实际吃不到的分量）。

### 3.4 美食类首图规律【共识】
- 近景特写要拍出食欲感（拉丝、热气、切面、酱汁），并搭配环境全景和吃的动作，保持统一调色 [S23]。
- 多店合集用拼图 + 大字编号（「5 家」「TOP3」）；单店用招牌菜特写 + 价格/地点角标。

### 3.5 AI 图与他人图片（硬红线）
- 【官方】《人工智能生成合成内容标识办法》自 2025-09-01 起施行，AI 生成的文字、图片、音视频都需要显式和隐式标识 [S16]。
- 【官方】小红书 2026-01 发布社区公约 2.0，要求主动标注使用了 AI 的内容 [S14]；2026-04-27 发布 AI 治理主张：创作者要如实标注，没有标注的由平台统一打标并开放申诉；**全托管 AI 账号会直接封禁**，偶尔使用 AI 的账号给予警告和限流 [S15]。
- 【官方】原创保护：平台近一年平均每月打击搬运笔记 600 万篇以上；转载需要事先授权，并在显眼位置注明来源、@原作者，否则失去推荐资格甚至被处罚 [S17][S18]。
- 落地：
  1. 我们的正文是 Claude 写的 → **每篇都打 AI 标识**（和 PLAN 一致）。
  2. **不要用 AI 生成「菜品照片」来代表真实餐厅**，这等于伪造真实体验，同时触碰「AI 造假」和「虚假内容」两条线。自动化路线只做**信息卡片 / 榜单卡 / 地图卡**（文字排版，不冒充实拍）；想要实拍图，就由 Chris 自己拍。
  3. 不能用 Google Maps、Yelp 或其他博主的照片。
  4. 「全托管」式运营有封号风险 → 保留人工审核环节，而不只是用 AI 标识来规避。

## 4. 正文与钩子

### 4.1 硬限制
- 【官方·产品限制】正文约 **1000 字**以内；2025-07 起开放了长文功能 [S26]。
- 【共识】图文笔记正文 100–400 字比较常见 [S26]。美食单店笔记建议 200–400 字，榜单类可以更长。

### 4.2 开头前两行【共识】
- 信息流展开前只能看到开头几行，所以**结论先行**：第一句话就交代「哪家店 / 哪个区 / 人均多少 / 值不值得去」，不要用「周末和朋友去了…」这类铺垫开场 [S25][S23]。
- 常用钩子：直接下判断（「这家我回购第 4 次了」）、给出数字（「$20 以内吃到 3 道招牌」）、抛出反差（「排队 1 小时，但我建议你别点招牌」）。

### 4.3 信息密度与结构【共识】
每 3–4 行分一段，重点句加粗或用 emoji 当项目符号 [S23]。美食单店推荐模板：

```
第 1 行：结论 + 核心利益点（店名/区域/人均/一句话评价）
📍 地址/区域 + 交通/停车
💰 人均（税前还是税后、要不要加小费，写清楚）
⏰ 营业时间 / 是否要预约 / 排队情况
✅ 必点：菜名 + 一句具体描述（口感、分量、价格）
⚠️ 可以不点 / 注意事项（至少一个缺点，增加可信度）
👥 适合谁：约会 / 一人食 / 带父母 / 聚会
结尾：一个具体、好回答的问题
```

- 榜单/合集模板：每家店一个块（店名 → 区域 → 人均 → 一道必点 → 一句话理由），最后给一句总结，例如「按场景怎么选」。

### 4.4 emoji 使用【共识】
- emoji 可以充当分段符、小标题和列表符号；短段落 1 个就够，重点段落最多 2–3 个；一篇笔记固定用 3–6 个核心 emoji，风格更统一 [S25]。
- 【传言】「用 emoji 的笔记互动率高 50% 以上」[S25] 没有出处。
- 落地：emoji 数量和密度**交给代码统计**，并设置上下限。

### 4.5 结尾互动引导（合规边界）【官方】
- 禁止**直接或间接诱导**关注、点赞、评论、收藏、分享；违规时会收到「笔记含诱导评论内容」一类的提示，处罚包括限流、禁止评论、封号 [S13][S20b]。社区公约 2.0 再次强调反对诱导关注和点赞 [S14]。
- 【共识】可以用**与内容相关的开放式问题**来引出真实讨论，例如「你心里列治文虾饺最好吃的是哪家？」；不要在每篇笔记末尾都用「点赞收藏关注」的模板 [S25]。
- 明确不要写：「评论区扣 1 发你完整名单」（诱导评论，而且是在往私信导流）、「收藏起来慢慢看」「关注我，下期更新 XX」（诱导收藏和关注）。

### 4.6 话题标签与长尾关键词【共识】
- 话题数量：各来源建议 5–8 个 [S23] 或 5–15 个 [S26]。**建议 5–8 个**，按以下结构搭配：
  - 核心/地域：#温哥华美食 #列治文美食
  - 细分：#温哥华早茶 #平价美食 #一人食
  - 场景/热门：#宝藏小店 #周末去哪儿
- 【共识】不要盲目加和内容无关的大流量标签，地域和垂类标签优先 [S30]。
- 【官方，间接】NoteLLM 会从笔记内容自动生成话题和类目 [S8]，说明话题是系统理解笔记语义的信号之一。**标签乱加会干扰分类。**
- 长尾关键词布局 [S28]：
  - 挖词：搜索框下拉词、「大家都在搜」、「猜你想搜」、相关搜索。
  - 位置：**标题 + 正文首句 + 小标题 + 话题**，自然出现，不要堆砌。
  - 新号优先做竞争小的长尾词（例如「温哥华 生日 餐厅 包间」），而不是「温哥华美食」。

### 4.7 导流与商业合作（硬红线）【官方】
- 不能出现微信号、其他平台名、外链、「私信我领…」[S19]。
- 所有商业推广都必须通过「蒲公英」报备；未报备的推广算违规营销，品牌方会被扣分和封禁 [S20]。社区公约 2.0 明确反对**伪造口碑、伪装素人、虚假营销** [S14]。
- 落地：如果以后接探店合作，要走报备并标注；在那之前，Jev 要检查每篇稿件是否「像软广」。

## 5. 美食探店赛道

### 5.1 容易爆的选题类型
| 类型 | 为什么有效 | 依据 |
|---|---|---|
| 榜单/合集（「X 区 N 家」） | 收藏率高、搜索命中率高、便于做信息卡 | 【共识】[S23][S30] |
| 平价/人均 | 性价比是最强的需求 | 【共识】[S23] |
| 宝藏小店/本地人才知道 | 稀缺感 + 好奇心 | 【共识】[S23] |
| 新店首发 | 时效性，搜索量有空窗期 | 【共识】[S30] |
| 节日/季节 | 需求集中爆发（例如温哥华 Dine Out 餐厅周、夏季夜市、樱花季、感恩节、圣诞、春节、中秋） | 【共识】（温哥华本地节点为本文推断） |
| 场景需求（约会/带父母/生日/一人食/深夜） | 身份标签 + 明确的搜索意图 | 【共识】[S12] |
| 避雷/踩雷 | 高唤起的负面情绪，点击高 [A1][A4]；但合规风险也高 | 见 5.3 |
| 网红店值不值（排队测评） | 信息缺口 + 争议讨论，容易带来评论 | 【共识】 |

- 【共识，单一数据集】2023 年 8 月探店类点赞前 500 的笔记里，**视频占 80% 以上，图文约 18%** [S24]。这意味着图文账号要在视频不擅长的地方竞争：**信息密度高、便于收藏的榜单、攻略和清单**。
- 【传言，单一来源】爆文的发布时段：13–18 点占 41%，18–23 点占 33% [S24]（统计的是国内时区）。温哥华账号的受众是本地华人，要换算成当地时间，最终以自己的数据为准。

### 5.2 用户最关心的信息字段【共识】
多个来源一致提到：**地址、人均、营业时间**，以及推荐菜、环境、服务 [S23][S30]。结合温哥华本地情况（本文推断）补充：
- 必填：店名、区域（Richmond / Burnaby / Downtown…）、人均（说明**是否含税和小费**）、必点菜、营业时间
- 强烈建议：是否要预约、排队时长、停车/交通、适合场景、分量、缺点
- 可选：支付方式、是否有中文菜单、包间、是否适合带小孩

→ 这些字段完不完整，应当**由代码根据结构化数据检查**（我们采集的数据里有就必须写进去），而不是让 Jev 去数。

### 5.3 避雷类内容的边界
- 【官方】2025 年 4 月平台集中治理「横测/拉踩」笔记，建议用「实测反馈」这类中性表达，替代「避雷」「黑料」等刺激性用词 [S21]（这次治理主要针对商品测评，但表述原则同样适用）。
- 【共识】对个人真实消费体验的合理吐槽受保护；**编造、夸大事实，以及「诈骗」「黑店」一类无依据的定性指控**，可能构成侵权并被投诉删除 [S22b]。
- 【共识】媒体观察认为平台对避雷帖的处理标准不透明，可能存在不通知的限流 [S22]。
- 落地：避雷类稿件改用「踩雷复盘 / 我不会再点的菜」这类说法；只写可以核实的事实（价格、等位时长、分量）加上主观感受，**不做人品或法律定性**，并且要有采集数据支撑（PLAN 第 5 步的 citation check）。

## 6. 学术与量化证据

| 研究 | 关键结论 | 对我们的含义 |
|---|---|---|
| Berger & Milkman 2012, JMR [A1] | 基于纽约时报 3 个月的全部文章：**高唤起情绪**（敬畏、愤怒、焦虑）更容易被转发，**低唤起**（悲伤）反而更少被转发；正面内容整体比负面更容易传播；**实用价值**和趣味性也会提升传播 | 惊喜、惊叹、「值回票价」的兴奋感 > 平淡的满足感；实用信息能带来收藏和分享 |
| Loewenstein 1994 [A2] | 好奇心来自「知道的」和「想知道的」之间的**信息缺口**；缺口越显著、越像是能被填上，驱动力越强 | 悬念标题要让读者觉得答案就在正文里，并且正文必须兑现 |
| Kuiken et al. 2017, Digital Journalism [A3] | 基于 Blendle 的改写标题和点击率数据：大多数（不是全部）clickbait 特征能显著提高点击，但**只靠这些特征无法预测**一个标题的效果 | 标题特征有用，但只是众多变量之一 |
| Robertson et al. 2023, Nature Human Behaviour [A4] | Upworthy 的 RCT（约 10.5 万个标题变体，3.7 亿次曝光）：负面词提高点击，正面词降低点击；中等长度的标题每多一个负面词，点击率约 +2.3% | 负面框架（「踩雷」「别点」）确实能提高点击，但要权衡第 5.3 节的合规风险和账号调性 |
| Brady et al. 2017, PNAS [A5]；2025 年重复实验和元分析 [A5b] | 每多一个道德-情绪词，转发量约 +20%；2025 年的元分析（27 项研究）修正为 **约 +13%** | 效应真实存在，但原研究基于政治话题；美食内容不适合道德化表达，仅作参考 |
| Tan, Lee & Pang 2014, ACL [A6] | 控制作者和话题后（同一用户、同一链接、不同措辞），**措辞本身会影响转发**；人类判断哪种措辞更好只比随机略强 | 支持「Claude 多写几版 → 模型打分筛选」；也提醒我们，人的直觉（包括 Jev 的直觉）准确率有上限 |
| Li & Xie 2020, JMR [A7] | 有图比没图互动更高（Twitter）；**高质量、专业拍摄**的图片在两个平台都更好；人脸和图文匹配在 Twitter 有效，在 Instagram 无效 | 图片质量比花哨更重要；人脸出镜在图片平台不一定加分 |
| Salganik, Dodds & Watts 2006, Science [A8] | MusicLab（14,341 人，48 首歌）：社会影响越强，成功的**不平等**和**不可预测性**都越高；最好的作品很少惨败，最差的很少成功，但中间的结果「什么都有可能」 | 质量只决定下限和上限，中间部分很大程度上看运气。要用多次发布的平均值来评估，不能拿单篇爆或不爆下结论 |
| Martin et al. 2016, WWW [A9] | Twitter 级联规模预测：即使数据量空前，最好的模型也**解释不了一半的方差**；理论上存在可预测性上限 | 阶段 1 的成功标准应该是「显著优于基线」，而不是「能准确预测爆款」 |
| Matias et al. 2021, Scientific Data [A10] | 公开了 Upworthy 32,487 个标题 A/B 测试（注意：2024 年发现约 22% 的测试存在随机化问题） | 可以作为英文标题特征的外部验证集（例如用来测试 Jev 在英文上的表现） |

- 【共识/行业数据，非学术】「标题带数字点击高 15%–20%」「奇数更好」等说法来自营销博客，没有同行评审 [S29]，只能标为【传言】。

**方法论含义**（给 PLAN 阶段 1 和阶段 3 用）：
1. 预测目标用 log(互动) 或点击率，并**控制粉丝数**（和 PLAN 一致）。
2. 保留 **20% 的随机探索**名额（和 PLAN 一致）。MusicLab 表明，只发高分稿会把噪声当成信号。
3. 标题和封面尽量做**配对比较**（同一选题、不同措辞），这是 Tan et al. 的思路，比跨选题比较干净得多。

## 7. 迁移性：Instagram / TikTok

| 规律 | 能迁移吗 | 说明 |
|---|---|---|
| 小流量测试 → 逐级放大；粉丝数不是直接因素 | ✅ | TikTok 官方明确：粉丝数和历史爆款**都不是**直接的推荐因素 [P1] |
| 首因效应（封面/首帧 + 标题） | ✅ 形式不同 | 小红书是双列信息流，比的是**点击率**；TikTok/Reels 是单列自动播放，比的是**前几秒留存和完播**。TikTok 官方把「看完长视频」列为强信号 [P1]；Instagram 对 Reels 的主要预测是「会不会转发、会不会看完、会不会点赞」[P2] |
| 实用价值 → 收藏、分享 | ✅ | Instagram 探索页的排序信号包括点赞、评论、**收藏**、分享的速度和数量 [P2]；在非粉丝触达上，私信分享（sends）更重要（Mosseri 的表态，第三方转述 [P3]） |
| 高唤起情绪、信息缺口、具体化 | ✅ | 学术证据本身就来自英文平台 [A1][A4][A6] |
| 原创、不搬运 | ✅ | Instagram 2024 年起在推荐里用原创内容替换搬运内容 [P4] |
| 本地关键词、搜索布局 | ✅ 大部分 | TikTok 官方把字幕、话题、声音列为内容信息信号 [P1]；关键词要换成英文或双语 |
| 20 字标题、3:4 封面大字 | ❌ 小红书特有 | IG 轮播图首图比例、Reels 封面、TikTok 文字覆盖各有规范，需要另外做 |
| 70% 用户搜索、「收藏夹」文化 | ⚠️ 部分 | 小红书的搜索属性最强；在 IG 和 TikTok 上，推荐流更占主导 |
| 中国广告法极限词、蒲公英报备、禁止提其他平台名 | ❌ 小红书特有 | IG 和 TikTok 有各自的品牌合作标注工具；加拿大本地的广告披露规定需另行核实 |
| CES 权重 | ❌ | 本来就是传言；各平台的信号不同 |

→ 做成网页工具时的建议：「文本判断题」（钩子强度、信息密度、具体性、合规）大部分可以跨平台复用；「格式题」（字数、比例、话题数）按平台单独配置规则（由代码实现）。

## 8. 候选 Jev 判断问题（草案）

**使用说明**
- Jev 返回的是概率。Score 用期望档位，Noul 用「是」的概率，Choice 用各选项的概率（见 `jevdev/jev.py` 里的 `flatten`）。
- 题目的**评估对象**已经标明。state 里只放这个对象需要的字段（例如标题题只给标题 + 账号定位），避免信息泄漏和干扰。
- Jev 官方说明英文效果最好、中文偏弱（见 PLAN）。建议阶段 1 做 A/B：**题干用英文 + 内容保持中文**，对比**全中文**，选效果好的版本。
- 档位描述要写成**能互相区分的具体特征**，避免「好 / 较好 / 很好」这种只有程度差别的措辞。
- 下面有些题（例如 T6、B8、B9）和代码正则有重叠：代码负责高召回的词表匹配，Jev 负责语义变体。两者都作为特征。

### 8.1 标题（对象：标题；state 另附账号定位「温哥华美食推荐」）

**T1 钩子强度** — Score
1. 流水账或纯描述，看不出利益点（「今天去吃了顿饭」）
2. 能看出主题，但没有让人想点开的理由（「温哥华一家港式茶餐厅」）
3. 有明确的利益点（价格、地点、品类中至少一个具体信息）
4. 利益点 + 情绪或态度（「终于找到…」「回购第 4 次」）
5. 利益点 + 悬念或反差，不点开就会觉得错过了什么

**T2 标题主类型** — Choice：{榜单合集, 单店推荐, 平价性价比, 踩雷/避坑, 新店首发, 场景需求, 节日季节, 值不值测评, 其他}

**T3 好奇心缺口** — Score
1. 信息全部说完，没有悬念
2. 有轻微的留白
3. 提出了一个问题，但答案可以猜到
4. 明确的信息缺口，答案需要点开才知道
5. 缺口强，而且和读者切身相关（「你可能一直点错了」）

**T4 情绪唤起类型** — Choice：{无明显情绪, 惊喜/惊叹, 满足/治愈, 吐槽/不满, 怕踩雷/焦虑, 失望/遗憾}（对应 Berger & Milkman 的高/低唤起分类）

**T5 口语化程度** — Score
1. 广告腔或新闻稿（「隆重推荐」「匠心打造」）
2. 书面、正式
3. 中性
4. 像朋友发的动态
5. 有鲜明个人语气，同时不油腻

**T6 夸张/绝对化表达（语义层）** — Noul：标题是否用了「最、第一、唯一」或等价的夸张说法（如「天花板」「封神」「吊打全城」「全网 XX」），或者对店铺做了无法核实的绝对化断言？

**T7 目标人群** — Choice：{未指向特定人群, 留学生/学生, 上班族, 情侣约会, 家庭/带父母/带娃, 新移民/游客, 美食爱好者/老饕}

**T8 具体性** — Score
1. 全是抽象形容词（「好吃」「绝了」）
2. 有一个模糊的具体点（「某区」「某家店」）
3. 有一个明确的具体信息（店名 / 菜名 / 区域 / 价格之一）
4. 多个具体信息组合在一起
5. 具体到读者看完标题就能做初步决定（去不去、值不值）

### 8.2 封面（对象：封面描述文字，即封面大字 + 画面描述；Jev 看不到图，所以由代码或 Claude 生成描述）

**C1 封面一眼可读性** — Score
1. 看不出主题
2. 能看出是美食，但不知道是哪里、为什么要看
3. 知道吃什么，或者知道在哪里
4. 「哪里 + 吃什么」都清楚
5. 「哪里 + 吃什么 + 为什么值得（价格、数量、结论）」都清楚

**C2 封面类型** — Choice：{单张菜品特写, 多图拼图, 大字信息卡/榜单卡, 环境/门面, 人物出镜, 其他}

**C3 封面与标题的关系** — Choice：{高度重复, 互补（各自提供不同信息）, 相互矛盾, 无关}

**C4 食欲感/视觉吸引力（按描述判断）** — Score
1. 没有食物主体
2. 食物是远景或不清楚
3. 食物清楚，但画面平淡
4. 近景，质感清楚（酱汁、热气、切面）
5. 近景 + 动态感或冲击力（拉丝、爆汁、满桌）

### 8.3 正文（对象：正文；B11、B12 需要额外提供采集到的店铺数据）

**B1 开头钩子（前两行）** — Score
1. 寒暄或背景铺垫（「周末和朋友…」）
2. 有主题，但没有结论
3. 前两行里给出了店或主题，以及一个具体信息
4. 第一句就给出结论和核心利益点
5. 结论 + 反差或悬念，让人想往下看

**B2 决策有用性（信息密度）** — Score
1. 只有感受，没有可用信息
2. 有少量信息，但不足以做决定
3. 能判断值不值得去
4. 能判断值不值得去，而且知道点什么
5. 看完就能直接行动（去不去、点什么、怎么去、花多少钱、要不要预约）

**B3 推荐菜明确** — Noul：正文是否点名了至少一道具体菜品，并说明了推荐理由？

**B4 适合/不适合人群** — Noul：正文是否说明了这家店适合或不适合什么人、什么场景？

**B5 真实体验感** — Score
1. 通稿式，换个店名也能用
2. 有一点具体细节
3. 有多处具体细节
4. 有只有到过现场才知道的细节（排队时长、服务细节、分量对比）
5. 细节 + 有取舍的个人判断（包括缺点）

**B6 平衡性** — Noul：正文是否提到了至少一个缺点、不推荐的菜或注意事项？

**B7 可扫读结构** — Score
1. 一大段文字
2. 有分段，但没有重点
3. 分段清楚
4. 分点或小标题清楚，关键信息醒目
5. 3 秒内就能找到地址、人均和推荐菜

**B8 诱导互动（合规）** — Noul：正文是否直接或间接要求点赞、收藏、关注、转发，或者用「评论扣 1」「评论区领取」一类方式诱导评论？

**B9 导流（合规）** — Noul：是否出现联系方式、其他平台名或谐音、外链，或者「私信我」「主页见」这类把用户引向站外或私域的表达？

**B10 软广感/伪装素人** — Noul：这篇内容读起来是否像商家通稿或未披露的商业合作（通篇夸赞、没有缺点、营销话术、强调优惠和活动）？

**B11 负面表述合规** — Noul（仅用于含负面内容的稿件）：负面评价是否超出了「个人体验 + 可核实的事实」，做出了「黑店」「骗子」「不卫生」这类定性或指控？

**B12 事实支撑（citation check）** — Choice：{所有事实性说法都有给定数据支撑, 少量说法无支撑, 多数说法无支撑}（state 同时放正文和采集数据）

**B13 结尾互动问题质量** — Score
1. 没有结尾，或用了「点赞收藏关注」模板（同时触发 B8）
2. 泛泛的「你们觉得呢」
3. 和主题相关的问题
4. 具体、好回答的问题（「你们在列治文吃过最好的虾饺是哪家？」）
5. 具体、好回答，还能引出有信息量的讨论或补充推荐

**B14 收藏价值** — Score
1. 看过就忘
2. 有一点参考价值
3. 下次去这家店时会用到
4. 在某个场景下会反复查（「带父母吃饭」「生日」）
5. 清单或攻略式，值得存下来做长期参考

**B15 个性与情绪价值** — Score
1. 平铺直叙，像说明书
2. 有少量态度
3. 有明确观点
4. 观点鲜明，而且有自己的语言风格
5. 读起来像一个具体的人在推荐，有记忆点

### 8.4 整篇（对象：标题 + 封面描述 + 正文 + 话题）

**W1 标题兑现** — Noul：标题或封面里的承诺（数字、结论、悬念）有没有在正文里完整兑现？（没兑现 = 标题党）

**W2 搜索意图匹配** — Score（state 附目标搜索词）
1. 和目标搜索词无关
2. 只是提到了
3. 部分回答了这个搜索需求
4. 完整回答了
5. 完整回答，而且比典型的搜索结果更好用（有结构、有取舍）

**W3 差异化** — Score（state 附该关键词下现有的前 10 个标题）
1. 和已有内容几乎一样
2. 角度相同，只换了店
3. 有一点新信息
4. 有明显不同的角度或信息
5. 提供了现有结果都没有的角度

**W4 主要互动预期** — Choice：{以收藏为主, 以评论讨论为主, 以点赞为主, 以转发给朋友为主}（用来做 CES 方向的特征，权重由回归决定）

**W5 定位一致性** — Noul：这篇笔记是否属于「温哥华（大温）本地美食推荐」的定位范围？

**W6 语义一致性** — Score
1. 标题、封面、正文、话题各说各的
2. 大体相关，但有明显偏离
3. 一致
4. 一致而且互相补充
5. 高度聚焦于同一个主题和同一个搜索意图

（共 32 题；阶段 1 可以先选 20 题左右跑一轮，按特征重要性删减。）

### 8.5 应由代码计算的特征（不要交给 Jev）

**标题**
- 字数（按 App 的规则计数，是否 ≤20）
- 是否含阿拉伯数字或中文数字，数字个数
- 是否含价格（`$`、人均、刀、加币）以及价格数值
- 是否含地域词（大温地名词典：Richmond / 列治文 / Burnaby / 本拿比 / Downtown / Kits…）
- 是否含品类词（品类词典）
- emoji 个数、「！？」个数
- 极限词和违禁词命中数（词表）
- 目标搜索词是否完整出现在标题中（字符串匹配）

**封面/配图**
- 图片张数；比例是否为 3:4；分辨率
- 封面大字的字数；文字面积占比（渲染时就能知道）
- 是否使用了 AI 生成图（由流程元数据决定，不用判断）

**正文**
- 字数、段落数、平均段长、最长段长
- emoji 个数和密度
- 关键信息字段是否完整：地址、人均、营业时间、推荐菜、预约和排队（对照结构化数据做字符串匹配）
- 目标关键词是否出现在首句，以及出现次数
- 导流正则（微信、vx、其他平台名及谐音、URL、电话号码）
- 诱导词正则（「点赞」「收藏」「关注」「扣 1」「评论区」）
- @ 用户的次数

**话题**
- 话题个数（建议 5–8）、是否含地域话题、是否含品类话题

**元数据 / 上下文**
- 发布时间（温哥华当地的小时、星期几）、距离节日或活动的天数（Dine Out、夜市季、春节、感恩节等）
- 店铺的外部评分、评论数、新店开业天数（来自采集数据）
- 和账号历史笔记、竞品笔记的相似度（用 embedding 计算）
- 账号粉丝数、账号近 N 篇的平均互动（控制变量）
- AI 标识是否已勾选（必须为真）

## 第 0 步（必须先做）：查清楚纸片马力欧到底是怎么做的
Chris 在小红书看到一条「纸片马里奥实现原理」的视频：画面是 Blender 里一个绑了骨骼的纸片马力欧（来自《任天堂明星大乱斗 X》），说它「实际上是……」（后半句被截断）。Chris 不确定纸片马力欧是不是 3D 建模。请查清楚，**每一条标出处和可信等级**（官方 / 开发者访谈 / 二手转述 / 模型拆包观察 / 推测）：
1. **角色**：
   - 是很薄、平面的网格（贴图纸片 + 骨骼蒙皮），逐帧切换的 2D 图片，还是真正有体积的 3D 模型？
   - 《折纸国王》《大乱斗 X》《贴纸星球》《色彩喷溅》各是什么做法？
   - 转身时像纸片一样翻过去是怎么做的？
2. **场景**：
   - 场景是有体积的 3D 模型、只是贴了纸纹和纸边（折纸、卡纸盒子），还是竖立的平面纸片？
   - 两种做法各占多少？
3. **镜头和光照**：是透视镜头吗？常用哪些机位？纸边、投影、纸的厚度是怎么表现的？
4. **纸片特效**：折叠、揉皱、撕开、撒纸屑是怎么做的？
5. **结论**：以上哪些做法能用我们「只写代码」的流程实现（Three.js WebGL，Playwright 逐帧截图，ffmpeg 合成）；哪些做不了，用什么替代。

## 硬性约束（不变）
- **只写代码，不用任何视频生成工具**。Codex 只用来画素材图（gpt-6-astra，reasoning effort 设 low）。
- 渲染流程不变：HTML 页面 → Playwright 逐帧 `renderFrame(t)` → ffmpeg。
- **three.js 放进仓库**（`video/vendor/three.module.js`，MIT 许可），不走 CDN，云端网络策略可能会拦。样片现在用的是 jsdelivr，要改掉。
- 史实规则照旧：`episode.json` 里的易错点、剧本评分的史实和儿童不宜闸门；只在表情、动作上夸张，不在史实上夸张。
- 每集必做 `video/logic_qa.py` 合理性复查；动作或画面的改动用 `video/motion_qa.py` 做改前 vs 改后。

## 画面规格（第 0 步查完后，按查到的做法修正）
1. **舞台**：一本打开的立体书放在暖色桌面上，每一场是一页。换场就翻页：整页纸景折倒，下一页的纸景带回弹「啪」地立起来（样片里已有弹起效果）。
2. **角色**：纸片人，有白色纸边和一点厚度；转身时像纸片一样翻过去（`puppet.js` 里已有 0.22 秒的翻面转身）。两种接法，按第 0 步的结论选：
   - A. 保留 `video/puppet.js` 的关节动画，把每个角色画到自己的离屏画布上，作为 CanvasTexture 贴到 3D 平面上。改动最小，走路、抱杆、表情全部保留；
   - B. 把部件拆成 Three.js 里的平面，用骨骼驱动（更接近纸片马力欧的做法，可以有轻微的 3D 转动）。
3. **场景**：竖立的纸片（城墙、城门、店铺、树），加上一部分**有体积的纸艺模型**（用 Box 等几何体贴纸纹、加纸边做成的卡纸房子、摊位）。远景用一张大背景纸。
4. **镜头（电影分镜）**：
   - 每 3–5 秒换一个机位或景别，用推拉、环绕代替横向平移；
   - 贴地仰拍：表现高度和威严（7 米木杆、商鞅）；
   - 俯瞰：表现人多（全城围观）；
   - 特写：反应镜头（小豆子眼睛变金块、爹捂眼、乌鸦「嘎」）；
   - **讲知识点、点题时镜头稳住**；
   - 不要长时间慢慢变焦（调研：会让孩子移开视线）。
5. **纸片物理（只用在高潮）**：
   - 金块一个个带碰撞地掉进怀里，堆成小山；
   - 告示上的「十」翻成「五十」；
   - 徽章解锁时撒纸屑。
   - 每集不超过 3–4 处。Jev 判断这个组合的过载风险是 0.59，是所有方案里最高的。
6. **司马光**：开头 0–1 秒从书页里弹出来说「考考你！」（`docs/开头3秒-司马光方案.md` 的 V2）；结尾点题。镜头拉远时能看到这本书就在他的书桌上。
7. **光照**：暖色主光 + 柔和阴影；纸纹、纸边要清楚。

## 第 0 步结果（云端，2026-09-28）

**可信等级**：官方 = 任天堂 / 开发商公开发布；访谈 = 开发者访谈原话；拆包 = 玩家从游戏文件里拆出模型后的描述；二手 = 百科、媒体转述；推测 = 我根据前面几项推的，没有直接出处。

### 一句话结论
纸片马力欧的角色**不是有体积的 3D 模型**，而是 3D 引擎里的**薄平面纸片**。
- 新作（《色彩喷溅》《折纸国王》）：基本就是**一块贴了图的长方形**，动画是一帧帧切换贴图，再加一点整体飘动。
- 旧作（《千年之门》《超级纸片马力欧》《贴纸星球》）：是**很多块贴图小平面 + 骨骼**拼成的纸偶。

场景则是**真正的 3D 模型**，做成「手工纸艺」的样子。小红书那条视频里，Blender 中「绑了骨骼的纸片马力欧」，应该就是后面这种「骨骼 + 多块平面」的纸偶（推测）。

| 《大乱斗》里的纸片马力欧奖杯 | 系列本身用 3D 模型，但角色大多画在平面上，所以奖杯也是平面 | [Mario Wiki: Trophy](https://www.mariowiki.com/Trophy_(Super_Smash_Bros._series)) | 二手 |

- **转身像纸片翻过去**：画面上表现为纸片绕竖轴转过去，或者横向压扁再展开。没有找到官方说明具体用的是「旋转平面」还是「缩放 X 轴」（**推测**：两种都能做出这个效果，我们现有的 0.22 秒翻面属于缩放那种）。
- **白色纸边**：新作角色一直有一圈白边，用来强调「扁」（[Mario Wiki](https://mario.fandom.com/wiki/Paper_Mario:_The_Origami_King)，二手）。白边是画在贴图里还是用几何体做的：**未能核实**。按「长方形贴图」的做法，最可能是画在贴图里（推测）。
- **没查到的**：小红书那条视频的原文；任天堂官方对角色结构的直接说明（「社长提问」原页打不开）。

### 2. 场景
- 场景是 3D 世界，做成手工纸艺：很多东西由手工材料做成，Boss 大多是文具（[Mario Wiki](https://mario.fandom.com/wiki/Paper_Mario:_The_Origami_King)，二手）。开发团队会准备**实物材料**做质感参考（VGC 访谈，访谈）。
- 立体场景和竖立纸片各占多少：**未能核实**。从画面看（推测），建筑、地形是有体积的纸盒、纸板模型；树、草、云、远景很多是竖立的纸片。

### 3. 镜头和光照
- 透视镜头，大部分时间是**斜俯视的跟随镜头**，战斗和过场会拉近、环绕（推测，来自画面观察，没有开发者说明）。
- 纸的厚度、投影：角色平面下面有一块圆形投影；纸边靠白边加轻微阴影表现（推测）。

### 4. 纸片特效
- 折纸展开、纸屑：折纸国王的核心设计就是「折纸和纸屑」（VGC 访谈，访谈）。
- 具体是骨骼、顶点形变还是粒子：**未能核实**。拆包提到用了 morph target，所以折叠、飘动很可能是顶点形变（推测）；纸屑是粒子（推测）。

### 5. 我们能做到哪些（Three.js 纯代码 + 2D 素材）
| 纸片马力欧的做法 | 我们能不能做 | 怎么做 |
|---|---|---|
| 角色是贴图平面 + 白边 | ✅ 能 | PlaneGeometry + CanvasTexture。现有纸偶和姿势图本来就带白纸边 |
| 旧作的「多块平面 + 骨骼」 | ✅ 能，但没必要 | 我们的 puppet.js 已经是这种纸偶，只是画在 2D 画布上 |
| 随风飘动、轻微弯折 | ✅ 能 | 平面多分几段，用顶点着色器做轻微弯曲 |
| 转身翻面 | ✅ 能 | 平面绕 Y 轴转 180°，背面换贴图，或者直接镜像 |
| 纸盒、纸板场景 | ✅ 能（简单几何体） | BoxGeometry / 挤出形状，贴纸纹，边缘加一圈浅色描边 |
| 竖立纸片的树、云、远景 | ✅ 能 | 现有素材直接贴到平面上 |
| 投影、暖光 | ✅ 能 | ShadowMap；平面贴图用 alphaTest，投影才是纸片的形状 |
| 纸屑、金块掉落 | ✅ 能 | 粒子，或者少量刚体（可以写简单物理，不用引物理库） |
| 复杂的折纸角色、折纸展开 | ❌ 很难 | 需要美术建模、手工 K 帧。替代：纸片折叠（平面沿一条线转动）、翻页弹起 |
| 精细的 3D 建筑模型 | ⚠️ 有限 | 只能用基本几何体拼；复杂建筑用竖立纸片（Codex 画图）代替 |

**角色接法推荐 A**：保留 puppet.js，把每个角色画到自己的离屏画布上，作为 CanvasTexture 贴到 3D 平面上。
- 这正是新作「贴图长方形」的做法：任天堂在新作里也从「骨骼 + 多块平面」退回到了一张贴图，说明一张贴图就够好看；
- 走路、抱杆、表情、白边修复、puppet_qa 全部保留；
- B（拆成 Three.js 骨骼平面）要重写整套关节动画，收益只是轻微的 3D 转动。这个效果 A 也能靠整体微转 + 顶点弯曲做到。

**要注意的坑**（推测，试做时验证）：
- CanvasTexture 每帧都要更新（`needsUpdate`）；
- 半透明边缘和深度排序会冲突，纸片用 alphaTest，不要用透明混合；
- 1080×1920 WebGL 截图的速度要实测。

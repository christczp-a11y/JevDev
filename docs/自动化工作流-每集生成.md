# 自动化工作流：每集怎么生成（第一集：三家分晋）

> 目标：给定一个《资治通鉴》故事，按这份文档一步步走完，得到一集可以发布的视频。Chris 只在 4 个检查点看东西。
> 依据：仓库里所有的调研、决策和踩坑记录（2026-09-29 通读整理，同日全面检查后修订）。**质检一律以 `memory/PITFALLS.md` 为准**，这里只写流程和过关条件。
> 维护：流程有变化就改这份文档。Chris 指出的问题记在 `memory/PITFALLS.md`，Chris 的决定记在 `memory/DECISIONS.md`；本文第六节只摘要。

## 一、分工和规则

### 模型分工（Chris 定，2026-09-29）
| 角色 | 模型 | 做什么 | 怎么调用 |
|---|---|---|---|
| **指导** | Opus 5.5，effort `xhigh`（界面里的 Extra） | 主会话：拆步骤、派活、做决定、和 Chris 沟通、更新 PITFALLS 和进度文件、commit / push。和 Chris 沟通一律用中文（P7）；Chris 的要求有两种理解时，先用一句话复述「输入是什么、要改或比较的是什么」，再动手（P6） | 开会话时选 Opus 5.5 + Extra |
| **重活** | Sonnet 5.5，effort `xhigh` | 写代码、生成剧本数据和场景、配音、渲染、跑质检脚本 | subagent `ep-builder` |
| **检查** | Opus 5.5，effort `xhigh` | 检查每一步交出来的东西，只查不改，给出通过或不通过和证据 | subagent `ep-reviewer` |
| **查资料** | Sonnet 5.5，effort `medium` | 史料原文、器物服饰、参考作品 | subagent `ep-researcher` |

不是 Claude 的工具：**Jev** 负责打分和闸门（剧本和开头用 `story.py`，合理性复查用 `logic_qa.py`，纸偶动作的改前改后对比用 `motion_qa.py`）；**Codex**（`gpt-6-astra`，reasoning low）负责画素材；**Edge TTS** 负责配音。

- 三个 subagent 定义在 `.claude/agents/`。新建或改动后，要**开一个新会话**才会加载。它们能用的工具和本文要对上：
  - researcher 没有写文件的工具（只有 Read、Grep、Glob、WebSearch、WebFetch），也不许改仓库里的文件：报告交给主会话，由主会话原样存档；
  - reviewer 没有 WebFetch：核对引文时用 Bash 下载维基文库原文页面，按原字搜索每条引文，逐字以下载的原文为准，不以网页摘要为准。
- 云端会不会加载项目里的 subagent，官方文档没写。云端找不到时，主会话用 Agent 工具的 `model` 参数指定 sonnet / opus。这时 effort 设置可能不生效，必读文件和权限限制也会丢：要把 `.claude/agents/<名字>.md` 的正文整段贴进任务说明，并写明「只查不改」「不 commit、不 push」。
- 主会话不自己做重活；只有很小的改动（比如一行参数）可以直接改。

### 每一步的循环
1. 主会话用**派活单**派活（查资料派给 researcher，其余派给 builder）；
2. builder 做（查资料是 researcher），按这一步的过关条件自己先检查一遍；
3. 主会话用**交检单**交给 reviewer 查；
4. 不通过：
   - reviewer 标「新坑」的，主会话在 PITFALLS 对应分类的末尾加一行，来源写「reviewer MM-DD 本地／云端」；
   - 标了已有编号的，在原行记「再犯 MM-DD」，写清检查为什么没拦住，并在同一轮让 builder 把检查补上（补不上的加进「待补的自动检查」）；
   - 然后交回 builder 修。**PITFALLS 只由主会话改。**
5. reviewer 再查。

同一步 3 轮还没过，就停下来问 Chris，不要一直自己改。

**派活单**（每次都用这个格式）：
```
集：tj01　步骤：第 5 步　轮次：2/3
输入：（路径）
要交的东西：（路径）
过关条件：（照抄第三节这一步的条件，和第二节「质检怎么算过」表里的相应行）
相关 PITFALLS：B6、B7、R11
上一轮 reviewer 没过的条目：（原样贴；第一轮写「无」）
不做：commit、push、发文件给 Chris、改这一步以外的文件
```
**交检单** = 派活单 + builder 报告原文 + 改了哪些文件 + 上次通过的提交号（reviewer 用 `git diff <提交号>` 看改动）。有退出码的质检，reviewer 自己重跑，不直接相信 builder 贴的结果。reviewer 的报告把过关条件逐条标 ✅ 或 ❌，附证据。

### 进度文件和中断恢复
- **每集一个进度文件 `video/stories/<集>/status.md`**。必须用 .md：`story.py` 会把这个目录里除 `episode.json` 以外的 .json 都当剧本读。reviewer 每次给出结论、每个检查点结束后，主会话更新它，然后 commit + push。内容：
  - 每一步的状态（没开始 / 做中 / 待查 / 通过 / 等 Chris）、轮次（x/3）、产出路径、reviewer 结论；
  - 定稿剧本的文件名、大问题、第 2 步定的基线；
  - 重跑用的完整命令（带环境变量和参数的配音、分场、渲染命令）；
  - 交付记录：每次发给 Chris 的日期、提交号、这一版改了什么。
- **每次发给 Chris 之前**，主会话先 commit（剧本、场景 JSON、素材、代码），把提交号记进交付记录。第 8 步改前改后对比用的就是这个提交号。
- **开工第一件事**（第 0 步之前）：主会话把 `memory/PROGRESS.md` 的「当前阶段」整段改成「tj01 三家分晋：第 N 步，详见 `video/stories/tj01/status.md`」。原来写试做集（徙木立信）的内容挪到「儿童历史动画（已完成）」下面，叫法改成「试做集」。之后每次更新 status.md，都同步改这一行。
- **中断后恢复**：先读 `memory/PROGRESS.md`，再读这集的 status.md，从第一个不是「通过」的步骤接着做。这一步的输入在 `video/out/`（不进 git）里找不到了，就按「重跑用的命令」重新生成，不凭记忆重写。PROGRESS.md 的「当前阶段」只写现在是哪一集、第几步，并指向这集的 status.md。

### 运行环境
- 第 1 步云端、本地都可以做；**第 2–9 步在同一台本地电脑上做完**：显卡渲染、Codex 登录、`video/out/` 里的中间文件都只在本地。`video/out/` 不进 git，换了环境就要从第 4 步重跑。
- **每个会话开工前先自检**，有一项不过就先修好再派活，不许为此跳过后面的质检（P8）：
  1. 命令一律用 `.venv/Scripts/python`（云端 `.venv/bin/python`），并设 `PYTHONIOENCODING=utf-8`（E5、E7）。系统的 `python` 是 3.14，没有 typesafe_sdk。**本文写的 `python video/...` 都指这个 Python**；
  2. 依赖装齐：`.venv/Scripts/python -m pip install -r requirements.txt`；
  3. 当前 shell 里 `TYPESAFE_API_KEY` 有值（Git Bash 的读法见 PROGRESS「怎么跑」）；
  4. `claude` 命令行已登录（`logic_qa`、`motion_qa` 用它当观察员）；
  5. 第 3 步之前确认 Codex 已登录（本地报「could not save」时的取图办法见 E4）；
  6. 第 4 步之前用 Edge TTS 合成一句测试，确认连得上（云端要设 `WSS_PROXY`，E3）；
  7. 第 7 步之前确认显卡渲染已经接上（第 0 步第 14 项）。
- `shot*.json` 这类通配符要在 Git Bash 里跑：PowerShell 不会展开，脚本自己也不展开。
- 长命令：
  - 预计 2–10 分钟的（Codex 出图、`frame` 质检、单场渲染）在前台跑，把 Bash 的 timeout 设到 600000；
  - 超过 10 分钟的（整集预览、定稿渲染、整集 `logic_qa`）用 Bash 的 run_in_background 跑，输出写到 `video/out/<集>/logs/<步骤>.log`，用 Monitor 等日志里出现结束行，再读日志末尾判断结果。不要在前台等到超时被杀（会留下没关掉的浏览器和渲染进程）；
  - 3D 渲染中途被打断，直接重跑同一条命令（按段续渲）；只有改过的场，才按第 8 步先删掉旧段。

### 目录和术语
- 目录：试做集（徙木立信）保留原来的 `ep01`、`ep01v2` 目录不动。正式各集用 `tj<两位集号>`（通鉴第几集），**第一集三家分晋 = `tj01`**，剧本、场景、输出目录都用这个名字。素材在 `video/assets/` 下的 `chars/`、`props/`、`sets/<布景名>/`；画风参考图是 `video/assets/ref/paper_style_ref.png`。
- **试做集** = 徙木立信（`ep01`、`ep01v2`）；**第一集** = 三家分晋（`tj01`）。不写「第 1 集」。
- **一场** = 一页纸景 = 一个 `video/scenes/<集>/shotN.json`（场景 JSON）= 分场脚本里的一个 `shotN()`；文件名里的 shot 指「场」。**镜头** = 一场里的一个机位，也就是 `build_stage3d.py` 镜头表 `cams` 的一行。
- **布景** = 一个地点的背景和摆设：2D 在 `video/sets/<名字>.json`，3D 现在写在 `stage.html` 的 `SETS` 里。
- 质检脚本用法里写的 `<剧本.json>` 指场景 JSON，不是台词剧本。
- **定稿剧本** = 选中的那一版候选文件本身（`video/stories/<集>/<版本>.json`），文件名记进 status.md，不另存一份（目录里多一个 .json，`story.py` 就多一版候选）。
- **第 0 步** = 本文第四节。`docs/画面改版-纸片马里奥风格-给云端.md` 里也有一个「第 0 步」（查纸片马力欧的做法），和本文无关。

  - **儿童动画调研** = `docs/儿童动画吸引力原理.md`（「规则 N」指它第 8 节表里的第 N 条）；
  - **运镜调研** = `docs/research/纸艺作品-运镜场景叙事.md`；
  - **角色调研** = `docs/research/儿童动画角色100-画风拆解.md`；
  - **诊断文档** = `docs/画面诊断与技术栈评估.md`。

## 三、每一步怎么做

### 第 1 步：史料简报（researcher → reviewer）
researcher 把简报全文交给主会话，由主会话原样存成 `video/stories/<集>/source.md`，状态行写「初稿，待 reviewer 核对」。

按通鉴顺序选故事，不挑着讲。唯一的例外是**核心就是暴力的故事**（刺杀、酷刑、杀妻，比如豫让、聂政、吴起杀妻）：视频整段跳过，直接接下一个故事，只在给家长看的正文里用一两句交代（Chris 09-29，S13）。

简报内容：
- 原文段落：维基文库《資治通鑑》，再用《史记》等交叉核对；每处引文 ≤ 20 字，都附出处链接；
- 事件时间线：哪些是本年的事，哪些是追述；
- 人物表：谁、做了什么、画的时候要注意什么。人名、地名都注拼音，标出生僻字和多音字（比如絺疵 chī cī；任章的「任」作姓读 rén；引用原文时「智伯行水」的「行」读 xíng，「沈竈產鼃」的「沈」通「沉」，读 chén）；
- 两段「臣光曰」的白话意思，以及可以给司马光点题用的原文短句；
- **儿童不宜清单**，每条写明怎么处理：整段跳过（故事核心就是暴力的，只能选这个，并写好给家长正文用的一两句交代）、这个情节不讲、皮影剪影一笔带过，或者只说「罚了」（S13）；
- 常见误传清单；
- **朝代器物服饰清单**：这个时代有什么、没有什么（钱币、帽子、衣领、兵器、酒器、坐具、地图）。给第 3 步画素材和 reviewer 检查用（S4–S6）。要画地图的（比如三家分晋交出去的「萬家之邑」），查清各地的相对方位：地图只画相对位置和城，不画现代省界和现代地名，不标河名；
- 下集预告：通鉴里紧接着的下一个**可以讲的**完整故事。核心是暴力的跳过，接它后面那个（S8、S13）。

reviewer：抽查每条引文，核对原文（方法见第一节）。标【未核实】的，不许写进剧本。

### 第 2 步：剧本（builder 写，Jev 打分，reviewer 查）
先写 `episode.json`：
- `core_question`、`core_answer`；
- `source`：本集用到的通鉴原文，按简报的顺序整段抄进来，转成简体。Jev 的史实闸门只对照 `source` 和 `pitfalls`（`docs/讲故事-方法与决策.md`），没抄进来的原文，剧本里讲了会被当成编的；
- `trick`：至少 2 条「为什么」的理由，要写办法为什么管用，不只列谁的毛病；

结构规则（全部来自已有的调研和 Chris 的决定）：
- **开头 0–5 秒用 V2 模板**：
  - 0–1 秒：司马光从书里弹出来，「考考你！」；
  - 1–3 秒：本集最怪的一幕；
  - 3–5 秒：二选一，带按钮和倒计时。

  不打招呼，不做自我介绍。7 秒内念出大问题。赌注在第 20 秒前讲清：做不成会怎样。

  **这三拍是剧本节拍，不是三个镜头**。画面上：
  - 第一个镜头从 0 秒起就有司马光，至少 3 秒（T11）；
  - 司马光在这个镜头里从书页上弹起来，3D 里不用试做集 2D 版的 `big_book` 书卡道具（T12）；
  - 最怪的一幕放在他身后，同一个镜头里；要切，也要等这个镜头满 3 秒以后。
  
  第 6 步写镜头表时照这个做。
- 一个大问题贯穿全集。节拍之间只用「但是 / 所以」连接，不用「然后」；三关一关比一关难，最后一关是真正的选择。
- 大问题在全片约 40%–60% 处关闭（或者先关一半）；关之前先打开下一个问题（「但是——？」）。
- 定一个**视角人物**贯穿三关，有欲望、有阻碍、有变化（不用小豆子，S7）。第一集全是大人，要提前定。
- 讲「为什么」先给反例，再揭晓（正反对照）。
- 「考你」约 4 次：开头 1 次，每关 1 次，每关都先让观众猜，再揭晓（留存调研第 7 节 F）。每次都是同一套仪式。停顿依次 1.0 / 1.2 / 1.2 / 1.8 秒（S10：以 Chris 的观感为准，不用调研的 2–3 秒）。停顿时倒计时、滴答声、角色「等你」的小动作和背景音乐都不停，不能是静止画面。揭晓只说「看答案！」，不管观众选哪个，都不说「答错了」。
- 金句只有一句，≤ 12 字，字面完全固定，全集说 3 次。
- 大约每 15–25 秒一个和剧情相连的小笑点，放在知识句前面或中间，不压在知识句上。让大人出糗，不单独给家长写梗段。
- 情绪最高点放在最后 25% 的时长里；最后 5–10 秒是温暖或悬念，不是说明。
- 结尾：「写书的人，来了——」→ 司马光用「臣光曰」点题（≤ 10 秒）→ 落到孩子自己的生活 → **道理之后接一个笑点或温暖的画面**（DECISIONS 09-27：结尾那句道理本身留不住人）→ 下集预告（一个人 + 一个问题）。

  - 结尾留不留试做集的「警枕滚落惊醒 →『我是司马光，就是小时候砸缸的那个！』」（剧本估约 11 秒），「点题 ≤ 10 秒」算不算这一段。

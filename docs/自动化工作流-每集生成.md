## 二、规矩（Chris 09-29）
1. **先出画面。** 工具只做挡住下一步画面的那一点，其他记进「待补」。
2. **review 只查成片**（第 7 步）：画面流畅不流畅、有没有逻辑错误、有没有闪烁、有没有穿模。其他时候默认不 review；只有 builder 报告「拿不准」、而且出错代价大、又没有脚本能查的时候，主会话才派 reviewer 查一次，只查一轮。
3. **小事自己决定。** 只有钱、账号，或者真正要 Chris 拍板的事才问，而且攒成一句话问。
4. **省 token。** 派活单和报告都写短；子代理只读它那一步的文件，不通读 PITFALLS 和整套流程；只重渲改过的场。
5. **一律用中文**和 Chris 沟通。给 Chris 看的永远是带声音、每秒 30 帧的视频，不给截图。

## 四、进度和恢复
- 每集一个 `video/stories/<集>/status.md`：每步的状态、产出路径、重跑用的完整命令、交付记录。每次发给 Chris 之前先 commit + push，把提交号记进交付记录。
- `memory/PROGRESS.md` 的「当前阶段」只写「<集>：第 N 步，见 status.md」。
- 中断后：先读 PROGRESS，再读 status.md，从第一个没完成的步骤接着做。`video/out/` 不进 git，缺了就按 status.md 里的命令重跑。
- Chris 提的每条修改：先在 `memory/PITFALLS.md` 记一行（原话 + 日期），再改（见第 8 步）。

## 五、运行环境
- Python 一律用 `.venv/Scripts/python`，设 `PYTHONIOENCODING=utf-8`；Jev 要 `TYPESAFE_API_KEY`（Git Bash 读法见 PROGRESS「怎么跑」）。本文件和各步文件里写的 `python` 都指它。
- 第 2–9 步在同一台本地电脑上做完：显卡、Codex 登录、`video/out/` 都在本地。
- `shot*.json` 这种通配符要在 Git Bash 里跑，PowerShell 不会展开。
- 超过 10 分钟的命令放后台跑，输出写到 `video/out/<集>/logs/`，看日志末尾判断结果。

# 自动化工作流（索引）：少儿版「古人云」动态漫画

> 2026-09-29 重写。**不再用 three.js，不用 AI 视频**：画面是 Codex 画的纸艺插画，动效由 Python 合成器用代码做。适用于每一集。
> 这是索引，**不要通读**：到哪一步，只读 `docs/workflow/` 里那一步的文件、这一集的 `video/stories/<集>/status.md`，以及那一步列出的规则文件。

## 目标：成片精美
画面干净、运动顺滑、字和声音讲究、节奏对。标准见 [第 7 步的精美标准](workflow/7-成片检查.md)。每一步都照这个标准做，review 只在成片时查一次，不来回返工。

## 定位（一句话）
**高质量的少儿版「古人云」**：保留古人云的快节奏、表情包式反应、特效卡点、古今对照；换成我们的纸艺画风、孩子能懂的梗、可靠的史实，不要血腥和恐怖。

## 二、规则文件（写剧本、分镜表、做特效时查）
- [节奏和特效](规则/节奏和特效.md)：剪辑节奏、镜头运动、人物表演、特效包、声音卡点；
- [钩子和吸引力](规则/钩子和吸引力.md)：开头 3 秒、全片钩子、系列感、标题、封面、正文、复盘；
- [版式和画风](规则/版式和画风.md)：版式、安全区、画风、字体、三种素材形态；
- [儿童安全和史实](规则/儿童安全和史实.md)：红线。

引擎还没建好之前，先按 [施工计划](施工计划-动态漫画引擎.md) 施工（A 合成器 → B 特效包 + C 检查工具 → D 试做第一场）。

## 三、分工（主会话按这个派活）
| 角色 | 模型 | 做什么 |
|---|---|---|
| 主会话 | Opus 5.5 xhigh | 派活、拿主意、和 Chris 沟通、维护 PITFALLS 和 status.md、commit / push |
| `ep-director` | Opus 5.5 xhigh | 剧本（第 2 步）、分镜表（第 4 步）、改剧本和分镜表（第 8 步）。创作的活给它，质量主要看这里 |

| `ep-reviewer` | Sonnet 5.5 xhigh（看图、逐帧检查的活一律用它，Chris 09-30） | 只查成片（第 7 步）和施工的特效样片，一次一轮 |
| `ep-researcher` | Sonnet 5.5 medium | 史料和参考资料 |

工具：Jev 负责打分和把关；**Codex `gpt-6.1-sol`（reasoning high）**画素材，一律用 `bash video/codex_gen.sh`；**Qwen3-TTS**（开源，本地显卡，`video/voice.py`）配音。

subagent 定义在 `.claude/agents/`，开新会话才会加载。**派活单**一段话写完：集 / 第几步 / 读哪个文件 / 输入 / 要交什么 / 过关脚本 / 不做（commit、push、发文件）。子代理只读它那一步的文件，不通读 PITFALLS 和整套流程。

## 四、规矩
1. 先出画面：工具只做挡住下一个画面的那一点，其余记「待补」。
2. review 只查成片；其他步骤由脚本把关。
3. 小事自己拿主意；只有钱、账号，或者真要 Chris 拍板的事才问，攒成一句话问。
4. 给 Chris 看的永远是带声音的视频；一律用中文。
5. Chris 的每条修改意见：先记进 `memory/PITFALLS.md`，再改（第 8 步）。

## 五、进度和环境
- 每集 `video/stories/<集>/status.md`：每步的状态、产出、重跑命令、交付记录。`memory/PROGRESS.md` 只写「<集>：第 N 步」。
- Python 用 `.venv/Scripts/python`，设 `PYTHONIOENCODING=utf-8`；Jev 要 `TYPESAFE_API_KEY`；Codex 要登录。
- `video/out/` 不进 git，缺了就按 status.md 里的命令重跑。

# 自动化工作流：每集怎么生成（第一集：三家分晋）

> 目标：给定一个《资治通鉴》故事，按这份文档一步步走完，得到一集可以发布的视频。Chris 只在 4 个检查点看东西。
> 依据：仓库里所有的调研、决策和踩坑记录（2026-09-29 通读整理）。**质检一律以 `memory/PITFALLS.md` 为准**，这里只写流程和过关条件。
> 维护：流程有变化就改这份文档；Chris 提的修改记在 PITFALLS，不记在这里。

## 一、模型分工（Chris 定，2026-09-29）
| 角色 | 模型 | 做什么 | 怎么调用 |
|---|---|---|---|
| **指导** | Opus 5.5，effort `xhigh`（界面里的 Extra） | 主会话：拆步骤、派活、做决定、和 Chris 沟通、更新 PITFALLS、commit / push | 开会话时选 Opus 5.5 + Extra |
| **重活** | Sonnet 5.5，`xhigh`（Extra high） | 写代码、生成剧本数据和场景、配音、渲染、跑质检脚本 | subagent `ep-builder` |
| **检查** | Opus 5.5，`xhigh` | 检查每一步交出来的东西，只查不改，给出通过或不通过和证据 | subagent `ep-reviewer` |
| **查资料** | Sonnet 5.5，`medium` | 史料原文、器物服饰、参考作品 | subagent `ep-researcher` |

不是 Claude 的工具：**Jev** 负责打分和闸门（剧本、开头、画面）；**Codex**（`gpt-6-astra`，reasoning low）负责画素材；**Edge TTS** 负责配音。

- 三个 subagent 定义在 `.claude/agents/`。新建或改动后，要**开一个新会话**才会加载。
- 云端会不会加载项目里的 subagent，官方文档没写。云端找不到时，主会话用 Agent 工具的 `model` 参数指定 sonnet / opus；这种情况下 effort 设置可能不生效。
- **每一步的循环**：
  1. builder 做；
  2. reviewer 查；
  3. 不通过：新问题先记进 PITFALLS，再交回 builder 修；
  4. reviewer 再查。
  
  同一步 3 轮还没过，就停下来问 Chris，不要一直自己改。
- 主会话不自己做重活；只有很小的改动（比如一行参数）可以直接改。

## 二、总流程
| 步 | 做什么 | 谁做 | 输出 | 过关条件 | Chris |

目录约定：试做集（徙木立信）保留原来的 `ep01` 目录不动。正式各集用 `tj<两位集号>`（通鉴第几集），**第一集三家分晋 = `tj01`**，剧本、场景、输出目录都用这个名字。

## 三、每一步怎么做

### 第 1 步：史料简报（researcher，Sonnet medium）
按通鉴顺序选故事，不跳。输出 `video/stories/<集>/source.md`，内容包括：
- 原文段落：维基文库《資治通鑑》，再用《史记》等交叉核对；每处引文 ≤ 20 字，都附出处链接；
- 事件时间线：哪些是本年的事，哪些是追述；
- 人物表：谁、做了什么、画的时候要注意什么；
- 两段「臣光曰」的白话意思，以及可以给司马光点题用的原文短句；
- **儿童不宜清单**，每条写明怎么处理：跳过、皮影剪影一笔带过，或者只说「罚了」（S13）；
- 常见误传清单；
- **朝代器物服饰清单**：这个时代有什么、没有什么（钱币、帽子、衣领、兵器、酒器、坐具）。给第 3 步画素材和 reviewer 检查用（S4–S6）；
- 下集预告：通鉴里紧接着的下一个完整故事（S8）。

reviewer：抽查每条引文，核对原文。标【未核实】的，不许写进剧本。

### 第 2 步：剧本（builder 写，Jev 打分，reviewer 查）
先写 `episode.json`：`core_question`、`core_answer`、`source`、`trick`（至少 2 条「为什么」的理由）、`pitfalls`，新增 `cast`（每个角色用哪个声音）。
然后写 **至少 6 版**候选剧本，格式和 `video/stories/ep01/N6_*.json` 一样，用 `python video/story.py video/stories/<集> --pairs` 比较。

结构规则（全部来自已有的调研和 Chris 的决定）：
- **开头 0–5 秒用 V2 模板**：
  - 0–1 秒：司马光从书里弹出来，「考考你！」；
  - 1–3 秒：本集最怪的一幕；
  - 3–5 秒：二选一，带按钮和倒计时。
  
  不打招呼，不做自我介绍。7 秒内念出大问题。
- 一个大问题贯穿全集。节拍之间只用「但是 / 所以」连接，不用「然后」；三关一关比一关难，最后一关是真正的选择。
- 「考你」2–4 次，每次都是同一套仪式。停顿依次 1.0 / 1.2 / 1.2 / 1.8 秒（S10）。揭晓只说「看答案！」。
- 金句 ≤ 12 字，全集说 3 次。
- 结尾：「写书的人，来了——」→ 司马光用「臣光曰」点题（≤ 10 秒）→ 落到孩子自己的生活 → 下集预告（一个人 + 一个问题）。
- 只夸张动作和表情，不改史实、数字和刑罚；不做现代货币换算；不让大人当坏人，不制造两代人对立；不叫观众「孙子」。
- 删掉一处铺垫，就要同时删掉对应的回收（S11）。
- 时长参考已交付的版本，约 155–160 秒（见第六节待定项）。

过关条件：
- Jev 闸门 `g_accuracy`、`g_kid_unsafe`、`g_generation` 都 < 0.5；
- 最长平淡段 ≤ 7 秒（目前最好的是 6.6 秒）；
- 两两对比胜出；
- reviewer 对照史料简报逐句核对。

✋ **检查点 1**：动手做画面前，先向 Chris 复述：大问题、节拍表、金句、「考你」的题目、儿童不宜内容怎么处理、下集预告。**Chris 确认后才进入第 3 步。**

### 第 3 步：角色和素材（builder 用 Codex，reviewer 查）
- 司马光：沿用现有设计。**先修掉姿势 2–5 的交领，宋代应为圆领（S6）**。
- 新角色按 `docs/research/儿童动画角色100-画风拆解.md` 的规范设计：
  - Q 版 2–3 头身；
  - 剪影一眼能认出来；
  - 一个主色 + 一件标志物；
  - 形状体现性格：圆 = 友善，三角 = 危险或聪明，方 = 固执；
  - 主角之间颜色要对比，配角降低饱和度。
- Codex：`-m gpt-6-astra -c model_reasoning_effort="low"`。
  - 必须附 `paper_style_ref.png`；提示词照抄现有纸片画风的描述；写明「只戴一顶帽子」（R12）。
  - 提示词里写上朝代器物清单的禁忌。
- 默认用**姿势图**（每个角色 5 个左右姿势）。只有动作很多的角色才做纸偶关节（侧面 + 45° 两套部件图，按 R4–R10 的规则来）。
- 拆图：绿底用 `split_sheet.py`，透明底用 `split_alpha.py`。有白边的部件跑 `strip_border.py`。
  - 命名：每个角色一个前缀（例如 `zb_` 智伯）。
  - 姿势图里带了别的角色的，登记到 `layout_qa` 的 `BAKED`（R11）。

reviewer：逐张对照朝代器物服饰清单，检查画风是否一致、有没有重复的帽子、有没有戏曲符号。

✋ **检查点 2**：把新角色造型拼成一张图，发给 Chris 确认。

### 第 4 步：配音和时间线（builder）
- `python video/voice.py <定稿剧本> video/out/<集>_voice [动作行号=秒 ...]`，旁白 `NARRATOR_RATE=+6%`。
- 用每句配音的真实时长排出全片时间线；语速超过每秒 5 个字就报警。
- **改过台词的句子要删掉旧的 mp3 重新合成**：现在的缓存按文件名命中，改了文字也不会重新合成。
- 混音（配音 + 音效 + 背景音乐）要能单独跑，不依赖 2D 成片（见第四节）。

### 第 5 步：分场和站位（builder → reviewer）
- 每集一个分场脚本，模板是 `video/build_ep01_v2.py` 的 `shotN()`。时间用台词行号和台词里的词来定位，不写死秒数。
- 场景 JSON 由脚本生成，不手改。
- 每集要有一个「看得见的概念物」，比如第 1 集的信用心：裂开再补回来。
- 过关条件：`python video/layout_qa.py video/scenes/<集>/shot*.json` 退出码为 0，检查重叠、被挡、说话时出画、重影（B6、B7、R11）。

### 第 6 步：3D 舞台和镜头（builder → reviewer）
- 场景：立体书摊在司马光的书桌上，一场就是一页。
  - 换场时，这一页折倒，下一页弹起来；
  - 背景纸围成一圈（圆柱内壁），脚下铺一圈草地；
  - 光源固定，影子贴图 4096；群众直接站在地上（T2–T4、T10）。
- **新地点要新做 3D 布景**。三家分晋有晋阳城、智伯军营、河水等；布景数据要从 `stage.html` 里挪出来，做成单独的文件。
- 镜头顺序（每一页）：
  1. 书桌机位交代场景；
  2. 电影镜头：仰拍表现高度，高机位表现人多，特写表现反应，还有跟拍和推近；
  3. 讲「为什么」时翻到纸景背面，看后面的机关；
  4. 结尾拉远，回到书桌。
  
  每 3–5 秒换一个机位。选择题、知识点、点题时镜头稳住。
- 构图一律用自动构图 `fit`：说话的人 ≥ 75% 在画面里，镜头对准的人 ≥ 85%；前景人物不能被切掉一半；被挡住不超过 30%。
- 纸片物理（比如水漫进来、金块落下）一集最多 3–4 次，只用在高潮。
- 前史和儿童不宜的内容，用皮影剪影一笔带过，加一点手持的抖动。
- 计分牌放在顶部单独一层（T6）。讲知识点时，画面上新出现的东西最多 2–3 样。
- 过关条件：
  - `build_stage3d.py qa <集>` = 0：有没有拍到书外面；
  - `build_stage3d.py frame <集>` = 0：人物入画、有没有被切掉一半、有没有被挡。

### 第 7 步：预览视频（builder 在本地用显卡渲染，reviewer 查）
- 在本地用显卡渲染：浏览器参数 `--use-angle=d3d11`，贴图 1 倍。实测每秒成片约 3.2 秒，整集约 8 分钟。**每秒 30 帧，带声音。**
- 跑闪烁检测：逐帧比较前后帧，报出闪烁的秒数和位置（T3、P2）。
- reviewer 看完整片：
  - 对照 PITFALLS 里所有 ⚠️ 项；
  - 对照史料简报；
  - 查衔接：前后镜头之间人物位置跳不跳、道具在不在。
- 过了才发给 Chris：用 SendUserFile 发整集，并附一句「这一版改了什么」。

✋ **检查点 3**：Chris 看视频。

### 第 8 步：修改循环（主会话派活）
Chris 每提一条意见：
1. 主会话**先在 PITFALLS 记一行**；是老问题再犯的，在原行记「再犯」；
2. builder 修改；
3. 跑受影响步骤的质检，外加改前改后对比（2D 用 `selfcheck.py`；3D 还没有对比工具，见第四节）；
4. **只重渲改过的场次**；
5. reviewer 检查；
6. 发给 Chris。

目标是每一轮 ≤ 10 分钟。把一轮意见一次改完，不要改一条发一次。

### 第 9 步：定稿渲染和混音（builder → reviewer）
- 高清：贴图 2 倍，在本地用显卡渲染，整集约 20 分钟。
- **发布前检查**：
  - 背景音乐的授权。现在的 MPT 曲库音乐**不能发布**（A2）；
  - 配音的商用授权：Edge TTS 能不能商用还没定；
  - 儿童不宜内容再查一遍；
  - AI 标注；
  - 字幕从头到尾对一遍。

### 第 10 步：发布（主会话）
- 标题 ≤ 20 字，写成「一件东西 + 孩子会问的问题」。
- 正文：给家长看的一层，加「3 个知识点」，再加这一集艺术加工的说明（比如按画面比例改了尺寸）。话题 3–5 个。不引导站外，不用极限词。
- 勾选「AI 生成」声明，正文最后一行也写上 AI 标注。
- 时间：北京时间 20:00–21:30 最好，即温哥华时间 05:00–06:30（11 月 1 日以后是 04:00–05:30）。次选北京时间 12:00–13:30。周末 09:00–11:00。建定时任务之前先问 Chris。
- **先「仅自己可见」**，Chris 确认后再公开（✋ **检查点 4**）。
- 发布后第 2 小时、24 小时、72 小时、7 天各采集一次数据：2 秒跳出、5 秒完播、完播率、平均观看时长、收藏率。找出流失最陡的 3 个地方，反馈到下一集的剧本。
- 【待验证】小红书 MCP 能不能发视频，以及怎么发。

## 四、开工前的工程准备（第 0 步，由 builder 做）
现在的流水线有很多地方写死了第 1 集（`ep01`），不改的话做不了新的一集。

**必须（做第一集之前）**
1. 按集参数化：
   - `build_stage3d.py` 的 `SCENES`、`AUDIO`、`OUT`、`SHOTS`、`REUSE` 改成按集读取，镜头表按集放进单独的文件；
   - `voice.py` 的 `CAST` 改成从 `episode.json` 读取；
   - `layout_qa` 的 `PINE`、`BAKED` 改成按布景和按集配置；
   - `logic_qa` 的 `KEY_MOMENTS` 改成按集配置。
2. 分场脚本模板化：从 `build_ep01_v2.py` 抽出通用部分（时间线、混音、拼接），每集只写自己的 `shotN()`。**混音要能单独跑**：现在 3D 版的声音借的是 2D 成片，必须先渲一遍 2D 才有。
3. 3D 布景数据化：`stage.html` 里写死的 `SETS`（qin_gate、classroom）和 `POLE` 挪成数据文件；新地点只加数据，不改代码。
4. 本地显卡渲染：`--gpu`（`--use-angle=d3d11`）加上 `?ss=` 预览贴图倍数（P1）。
5. 闪烁检测：直接读预览视频检测（T3、P2）。
6. 没有 Jev key 时，质检直接报错，不许静默跳过（P8）。
7. `voice.py` 的缓存改成按台词文字判断，文字变了就重新合成。
8. `story.py`：观众年龄改成 6–12 岁（现在写的是 6–9 岁）；评分标准里「横版闯关」的描述改成 3D 立体书；修掉标题是字符串时被拆成单字拼接的问题。

**边做边补**
- 3D 版的改前改后对比工具（相当于 2D 的 `selfcheck.py`）；
- 朝代器物服饰的自动对照（S4–S6）；
- 发布前检查脚本（A2、S13）；
- 伏笔和回收的配对检查（S11）；
- 删掉或修好 `video/stage3d/render_stage.py`：它引用的机位名称已经不存在，一跑就报错；
- 司马光的纸偶部件、眉毛表情。

## 五、第一集：三家分晋的输入
第 1 步的史料简报初稿已经完成：`video/stories/tj01/source.md`，**还要 reviewer 逐条核对**。要点如下：

- **通鉴怎么排**：先写前 403 年周王把三家封为诸侯，再用「初，」倒叙智伯怎么从最强走到灭亡。
  - 片子可以照这个结构：开头是封诸侯的仪式，中间讲智伯的故事，结尾回到封诸侯，由司马光点题。
- **推荐的大问题**：「**最强的智伯为什么输了？**」
  - 线索：五贤一不仁 → 宴会上欺负人 → 到处要地 → 不听劝；
  - 点题用原文「才者，德之資也；德者，才之帥也」。
  - 备选：「有人跟你要地，你给不给？」（仓库里已有这个开场设计）、「赵襄子为什么逃到晋阳？」。
- **开头 5 秒**：司马光「考考你！」→ 大水漫到城墙上的刻度「还差三版」、灶里跳出青蛙 → 二选一：「有人跟你要地，你给不给？」
- **角色**：
  - 新画：智伯（最高大，拿弓）、赵襄子、韩康子、魏桓子、智果、絺疵、张孟谈、周威烈王；
  - 可选：尹铎、段规、豫让；

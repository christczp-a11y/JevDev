# 我们的小红书爆款工作流（v2，2026-09-27）

> 这份工作流是这样来的：把网上流传的「小红书爆款 10 个 Skill」逐个找到原始资料，提取出 66 条候选规则；再用 Jev 在 392 篇温哥华美食赛道笔记上逐条检验，看哪些规则真的和互动有关，然后按官方「自动研究」方法跑了 3 轮自我优化，最后在留出测试集上验收。
> 相关文件：
> - 规则来源：`docs/research/10个skill-提取.md`
> - 检验程序：`scripts/autoresearch.py`、`scripts/rule_catalog.py`、`scripts/composite.py`
> - 结果数据：`data/autoresearch/`

## 1. 一张图看流程

```
选店 ──► 采集评价 ──► Jev 逐条判断评价 ──► 代码汇总餐厅画像
            (Google 50 条 / 小红书笔记和评论 / Reddit 经 Codex)
   │
   ▼
Claude 写 4 篇不同角度的草稿 ◄── 写作规则（prompts/xhs_writer.md，已写入数据验证过的规则）
   │
   ▼
代码检查（禁用词、字数、标签数）+ Jev 逐句核查（每句都要在评价里找得到依据）
   │  有问题的句子 → Claude 只改这几句 → 再核查
   ▼
Jev 合规闸门（极限词、诱导互动、导流、广告感、定性指控、冒充到店）── 任意一项不过就淘汰
   │
   ▼
渲染每篇的卡片 → Claude 看图描述封面 → Jev 按 21 条验证过的规则打「复合分」
   │
   ▼
选稿：80% 选复合分最高的，20% 随机探索 ──► 草稿包 ──► Chris 审核 ──► MCP 发布（首篇仅自己可见）
   │
   ▼
第 1 / 3 / 7 天追踪互动（track.py）──► 定期重跑自动研究，更新规则和复合分（自我优化）
```

分工：代码负责抓取、计数、计算和执行；Claude 负责写作和看图描述；Jev 负责所有判断（评价情感、事实核查、合规、规则打分）；Chris 负责审核发布，以及点赞、评论、私信这些互动。

## 2. 10 个 Skill 的结论

「检验结果」一栏来自 392 篇赛道笔记（开发集 297 篇，留出测试集 95 篇）。

| Skill | 我们拿来用的部分 | 检验结果 | 结论 |
|---|---|---|---|
| huashu-topic-gen（选题） | 多角度出稿再择优 | 流程类，没法用数据检验；我们本来就是每次写 4 个角度 | ✅ 已有 |
| 小橡皮AI（润色） | —— | 它的目的是降低 AI 检出率，和我们必须标注 AI 冲突 | ❌ 不用 |
| content-planning（规划） | 内容支柱、固定节奏 | 流程类。选题数据：「避坑」「平价」定位的标题互动更低，「发现好店」式更高 | 🔶 用于选店和角度 |
| huashu-research（调研） | 来源分级、写前核验 | 流程类；我们的「评价聚合 + 逐句核查」已经覆盖 | ✅ 已有 |
| xhs-writer（写作） | 卡片结构、humanizer 去 AI 味清单 | **「配文 100–300 字」被数据否定**：这个区间的笔记互动最低（开发 −0.19，测试 −0.50），300 字以上更好。去 AI 味的几条规则都没看出和互动有关 | ⚠️ 字数反着用；去 AI 味只当可读性要求 |
| zhongcao（种草语感） | 探店五段结构 | 五段结构完整度和互动没有关系。「作者本人的感叹」「像真实食客在讲亲身经历」是正相关，但我们不能冒充到店，只有 Chris 真去过时才能用 | 🔶 见第 5 节 |
| title-writing（标题） | 开头放钩子、制造好奇 | **验证通过**：好奇缺口、开头就有吸引点、口语化。它推荐的煽动词也和互动正相关，但违反平台规则，不能用 | ✅ 写入规则 |
| hashtag-optimization（标签） | 5–8 个、分层、要相关 | 标签分层、标签相关度都和互动没有关系 | ⚪ 只当规范，不指望涨流量 |
| guizang-social-card（视觉） | 安全区、字号、单焦点、强调色 | 能从封面描述判断的几条（单焦点、强调词、贴纸、水印、大字醒目度）都没有关系。只有「画面偏暗」是负相关（开发 −0.12，测试 −0.21）。「封面大字让人好奇」被模型保留，但单独看不显著 | 🔶 当设计规范；封面还需要做实验 |
| content-performance-analysis（复盘） | Top / Bottom 复盘 | 我们的自动研究循环就是这个思路的量化版：每轮让 Claude 看预测最差的笔记，提出新规则 | ✅ 已实现 |

## 3. 验证通过的规则（已写进 `prompts/xhs_writer.md`）

数字是扣掉「采样来源、发布天数、是否视频」之后，这条规则和互动（点赞 + 收藏 + 评论）的 Spearman 相关，格式为「开发集 / 留出测试集」。开发集上显著、而且测试集上方向一致，才算通过。

**标题（每组样本 297 / 95 篇）**
| 规则 | 相关 |
|---|---|
| 留一个点开才知道的缺口（好奇心） | +0.34 / +0.24 |
| 惊喜、发现的情绪 | +0.31 / +0.20 |
| 像朋友随口分享（口语化） | +0.27 / +0.21 |
| 作者本人的感叹（第 1 轮 Claude 提出） | +0.27 / +0.19 |
| 对店的态度偏正面（第 3 轮 Claude 提出） | +0.26 / +0.30 |
| 有钩子、有利益点 | +0.27 / +0.10 |
| 带地名 | +0.21 / +0.13 |
| 带 emoji | +0.19 / +0.13 |
| 开头几个字就有吸引点 | +0.15 / +0.18 |
| 「发现好店」句式 | +0.12 / +0.13 |
| 只是名词标签堆砌（第 2 轮 Claude 提出） | **−0.24 / −0.17** |
| 「避坑」定位 | **−0.22 / −0.20** |
| 把信息全塞进标题（越像说明书越差） | **−0.19 / −0.08** |
| 「平价」定位 | **−0.12 / −0.16** |
| 靠米其林、获奖这类外部背书当卖点（第 2 轮 Claude 提出） | **−0.14 / −0.05** |

**正文（有正文的笔记只有 96 / 34 篇，结论相对弱）**
| 规则 | 相关 |
|---|---|
| 标题的承诺在正文兑现 | +0.31 / +0.33 |
| 像真实食客讲亲身经历，不像营销号 | +0.27 / +0.33 |
| 能帮读者做出去不去、点什么的决定 | +0.23 / +0.24 |
| 有值得收藏的具体信息 | +0.21 / +0.15 |
| 正文 100–300 字 | **−0.19 / −0.50** |

**封面**：画面偏暗 **−0.12 / −0.21**。

**和互动正相关、但我们不能用的**：标题用煽动词（+0.32 / +0.18）、用极限词（+0.30 / +0.25）。它们违反社区规则，只作为合规闸门拦截。惊喜和好奇这两条能带来类似的效果，而且不违规。

**检验过、没看出关系的**（部分）：标签分层和相关度、正文五段结构完整度、清单格式、去 AI 味、模糊归因、先讲痛点、标题点名人群、搜索关键词组合、封面单焦点、强调词、贴纸、水印、大字醒目度，以及 Claude 在循环中提出的「思乡 / 和国内对比」「网红单品」「节日热点」「系列内容」「排队式社会证明」。这里说的是「在这 392 篇里看不出来」，不等于没有用。样本再多一些，可以重新检验。

## 4. 自我优化和自我验收：做了什么，结果如何

1. **第 0 轮**：46 题，由我们已有的标题题和正文题，加上 10 个 skill 的规则组成。开发集交叉验证 RMSE：基线 1.309，基线 + Jev 1.223。
2. **自动研究 3 轮**（照 TypeSafe 官方 cookbook「autoresearch feature discovery」）：每轮 Claude 看预测误差最大的 12 篇笔记，提出新题、改题、删题；Jev 给所有笔记作答；用交叉验证决定去留。
   - 第 1 轮照官方规则，新题只要答案不是千篇一律就保留。结果收下 7 道新题后，误差反而变大（1.223 → 1.235）。**我们的样本只有官方示例的 1/7**，所以改成新题也必须让误差下降才保留，并按新标准复查了第 1 轮的新题（1.214）。
   - 第 2、3 轮：1.214 → 1.197 → 1.192，已经接近平台期，所以停止。
3. **留出测试集验收（只看一次）**：
   - **39 题的大回归没通过**：测试集 RMSE 1.212，比基线 1.135 还差。这是过拟合，一道一道挑题的过程让模型对开发集「量身定做」了。
   - **单条规则通过**：开发集显著的 23 条里，21 条在测试集上方向一致（纯靠运气的概率约十万分之三）。
4. **改用复合分**（官方「composite scoring」模式）：开发集上显著、而且我们能照着写的 21 条规则，各自标准化后按方向等权平均，没有需要拟合的权重。
   - 测试集上，复合分和「扣掉混杂因素后的互动」的 Spearman 是 **+0.29，95% 区间 [+0.10, +0.46]**。
   - 只用 Jev 判断的 16 条是 +0.24；只用代码能数的 5 条是 +0.26。两者强度相近，合起来最好。
   - 每条规则的标准化值截断在 ±3 以内。不截断时，稀有特征（比如标题里用「你」）出现一次就是四五个标准差，会压过其余所有规则。
   - ⚠️ 这是第二次看测试集，结论要打一点折扣。等下一批新采集的笔记到了，再做一次干净的检验。

**诚实的结论**：Jev 在这里的价值是把「好奇心」「标题承诺有没有兑现」「是不是名词堆砌」这类代码数不出来的判断变成数字，让我们能用数据验证规则、按规则选稿。它能把选稿从「凭感觉」变成「有 +0.29 相关的依据」，但不能保证爆文。互动量的大头由发布时间、账号权重、平台分发决定，这些都不在内容里。

## 5. 最重要的三个发现（影响后续方向）

1. **「真人亲历感」和互动正相关**（正文 +0.27 / +0.33，标题的本人感叹 +0.27 / +0.19），但我们不能冒充到店。唯一合规的办法是 Chris 真的去吃，把体验通过 `--my-notes` 写进去。**建议每周至少 1 篇由 Chris 亲自去过的店**。
2. **标题要一句有态度的话，要有好奇心**。不要写成名词标签堆砌，也不要写成「避坑」「平价」这类定位。这是证据最强的一组规则。
3. **正文要写足，350–700 字**，不要照 xhs-writer 的 100–300 字。

## 6. 还没解决的问题

- **作者粉丝数没控制**：大号的标题往往写得好，互动也高，部分相关可能来自账号本身。用 MCP 查 284 个作者主页可以补上，但要用新号大量浏览别人主页，需要 Chris 决定。
- **封面**：赛道里纯文字卡封面只占 4%（15 篇），没法判断我们的文字卡和实拍图谁更好。guizang 明确认为餐厅帖没有实拍图不行。需要 Chris 拍照，或者用我们自己的帖子做 A/B。
- **有正文的样本少**：测试集只有 34 篇，正文规则的结论偏弱。
- **相关不等于因果**：规则是「爆文的共同特征」，照着写不一定就会爆。最终要看我们自己帖子第 7 天的数据。

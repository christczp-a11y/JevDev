# 第 7 步：成片检查（唯一固定的 review）

谁做：`ep-reviewer`（Sonnet 5.5 xhigh；Chris 09-30：看图片、逐帧检查的活用 Sonnet），只查一轮，**限时 30 分钟**（PITFALLS P17：查了 2.5 小时）。顺序：先**只看每秒 1 帧的联系表，用五六句话复述这一集讲了什么**（只看画面和字幕，不看剧本），复述不出来或复述错的地方就是「看不懂」的问题（P19、S28）；再对着**每镜停留时间表**（`review_frames.py` 出的）逐镜过一遍「这一镜要交代的东西看清了没有」（M10）；再看自动检查报告；再只放大看有疑问的地方（最多 10–15 处），不逐镜逐帧抽查；到 30 分钟就按已查到的交报告。
读：本文件、成片、builder 出的联系表（每秒 1 帧）和动作段抽帧（每秒 10 帧）、自动检查报告。

## 精美标准（成片要达到的样子）
| 方面 | 标准 |
|---|---|
| 画面 | 插画干净：没有锯齿、断掉的白纸边、残留的绿边，没有压缩糊；屏幕显示 ÷ 原图 ≤ 1.3；同一个人前后长得一样；同一段的色调统一 |
| 运动 | 所有运动都有缓动，不抖、不跳帧；人物进场出场有弹性；转场有设计（翻页、纸片擦过、笔刷），除了卡点硬切，不生硬 |
| 文字 | 只用两种字体；字幕不压脸；标题条、人名牌、字幕的位置每集一样；没有缺字、没有繁体 |
| 声音 | 配音清楚，整集响度一致（−16 LUFS）；有人说话时音乐自动压低；每个特效都有音效而且卡点；没有爆音、没有突然静音 |
| 节奏 | 每分钟 18–24 个镜头；讲知识点时收住；没有静止超过 1.5 秒的画面 |

## 只查这五类（加上面的精美标准）
| 类别 | 查什么 |
|---|---|
| **流畅** | 镜头运动顺不顺、有没有一跳一跳；切点有没有卡在台词和拍子上；有没有画面「死」住；快切是不是太碎 |
| **逻辑** | 旁白说到谁，画面上是不是谁；人物朝向对不对；前后镜头接不接得上；东西有没有凭空出现；朝代器物服饰对不对 |
| **闪烁** | 看自动检查报告，报出的秒数逐个打开看；有没有刺眼的闪 |
| **穿模** | 人和人、人和道具有没有叠在一起互相穿过；有没有脚悬空、被切一半；字和贴纸有没有盖住脸 |
| **停留时间**（M9、M10，Chris 10-01） | 每一镜出现的时间够不够看清它要交代的东西，不能一下就跳走：讲事的画面（泡泡、属性卡、地图、砸字）看得见 ≥ 2 秒；一般镜头 ≥ 1.5 秒，短于 1.5 秒的只许在高潮快切里；字多的画面按字数给够读的时间 |
| **素材和遮挡**（P19） | 大块空白、露出的接缝、素材没铺满（M7）；字幕挡脸、贴纸特效盖住主角（M6、M8） |
| **看不看得懂**（P19） | 只看画面和字幕，能不能复述故事；关键转折有没有台词交代（S28）；下集预告讲没讲清（S29） |
| **儿童安全** | 有没有吓人、血腥的画面或字；梗是不是孩子的梗（按 `docs/规则/儿童安全和史实.md`） |

## 报告（要短）
- 通过或不通过；
- 每个问题写：秒数、现象、类别；
- 分成「挡住交付」和「小问题」两类。挡住交付的交回 builder 修，修完主会话看自动检查的结果，不再重查；小问题记下来，下一集改。

## 发给 Chris
先 commit + push，提交号记进 status.md；用 SendUserFile 发视频，附一句「这一版改了什么」。**第一集先发第一场样片，Chris 通过了再做整集。**
- **手机端上限 30 MiB**：`render.py` 的成片码率很高（2 分钟约 300 MB），发之前转一份手机版：`ffmpeg -i 成片.mp4 -c:v libx264 -preset slow -b:v <码率> -pass 1 -an -f mp4 NUL`，再用 `-pass 2 -maxrate 1.5倍 -pix_fmt yuv420p -r 30 -c:a aac -b:a 128k -movflags +faststart` 出片；码率 ≈ 28 MB × 8 ÷ 秒数 − 128k（127 秒约 1600k）。超过 30 MiB 的文件只能在桌面 app 里看到。整集（3 分钟以上）手机版用 720×1280（同码率比 1080 宽清楚）。上传还有 30 秒的超时：网慢时 25 MB 也会失败，就用 `ffmpeg -i 手机版.mp4 -c copy -f segment -segment_times <中间秒数> -reset_timestamps 1 片段_%d.mp4` 切成上下两段各发一次（不降画质），失败的那段重发。

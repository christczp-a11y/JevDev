# memory/ — 项目长期记忆（检索入口）

对话上下文会被 compact / clear，**这里的文件不会**。所有跨会话需要保留的信息都写在这里，并提交推送到 git。

## 恢复流程（新会话 / clear / compact 之后）
1. 读 `memory/PROGRESS.md` —— 当前在做什么、下一步是什么
2. 做视频：先读 `docs/自动化工作流-每集生成.md`（索引，很短），到哪一步只读 `docs/workflow/` 里那一步的文件和它列出的 `docs/规则/`；引擎还没建好时读 `docs/施工计划-动态漫画引擎.md`
3. 开工前跑一次装机检查 `bash scripts/cloud_setup.sh`（全部通过才开工）；用 Jev 之前读 `.claude/skills/jev-decisions/SKILL.md`
4. 按需读 `memory/CONTEXT.md`（环境与约束）、`memory/DECISIONS.md`（已定决策，不要重新讨论）
5. 需要细节时再检索：`grep -rn "关键词" memory/`

## 文件分工
| 文件 | 内容 | 更新时机 |
| --- | --- | --- |
| `PROGRESS.md` | 当前状态、进行中、下一步、阻塞项 | 每完成一个步骤 / 会话结束前 |
| `PITFALLS.md` | 踩坑清单：现象、根因、规则、自动检查；交付前检查清单 | **Chris 每次要求修改时，先记一行再改**；同一个坑再犯，在原行记「再犯」并补上检查 |
| `DECISIONS.md` | 决策记录：决定了什么、为什么、放弃了什么 | 做出任何不该被重新讨论的决定时 |
| `CONTEXT.md` | 环境事实、工具、限制、外部服务 | 环境变化时 |
| `PRODUCT.md` | 产品定义：用户、定位、形式、指标 | 产品认知变化时 |
| `log/YYYY-MM-DD.md` | 当日会话流水（简短） | 每个会话 |

## 写入规则
- **先写文件，再继续工作**：重要结论产生后立即落盘，不要攒到最后。
- 写事实和结论，不写过程废话；每条尽量一行。
- `PROGRESS.md` 保持短小（< 80 行），历史挪到 `log/`。
- 不写密钥、token、个人隐私。
- 改完即 commit + push（容器是临时的，未推送 = 丢失）。

# PRODUCT — 产品定义

> 状态：方向初稿（2026-09-27），关键假设未验证。标 [待定] 的不要自行假设。

## 一句话
Claude × Jev 的小红书运营工作流：Claude 批量写稿，Jev 打分筛选；用真实发布数据反向优化写作，形成闭环。

## Chris 原始设想
- Claude 批量生成潜在爆文，Jev 分析决策发布
- Claude 指挥 Jev 抓取爆火贴文、分析内容，反向优化 Claude 写作技巧

## 已纠正的事实
- Jev 不浏览、不抓取网页。它只对给定输入做类型化判断（Choice / Noul / Score）并返回概率。抓取由代码完成（Playwright 等），Jev 只负责判断抓回来的内容。

## 修正后的架构（提案）
1. 采集层（代码）：博主自有账号数据为主；竞品 / 爆款样本为辅（来源合规性待定）
2. 判断层（Jev）：对每篇笔记按维度打分（钩子强度、情绪价值、信息密度、定位匹配度…），并做合规检查（Noul）
3. 生成层（Claude）：按写作指南批量出稿 → Jev 筛选 Top N → 人工确认发布
4. 反馈层：Jev 维度分 × 真实表现（曝光 / 点击 / 互动 / 涨粉）→ 算出哪些维度真正有效 → 更新 Claude 写作指南

## 关键风险
- 数据获取：小红书反爬 + 用户协议 + 法律风险；当前云环境网络策略也拦截了 xiaohongshu.com
- 平台治理：AI 生成内容需要标识（《人工智能生成合成内容标识办法》2025-09-01 施行）；小红书治理 AI 托管 / 批量内容（具体条款待核实）
- 可预测性：爆款受随机性和社会影响很大（Salganik et al. 2006 MusicLab）；只分析爆款会有幸存者偏差，必须有非爆款对照样本
